# songwriting-and-ai-music

用户要写歌词、作曲、生成歌曲/主题曲/有人声的音乐时读本 skill。最终音乐由 `generate_audio`（音乐）生成；本 skill 覆盖两件事：词曲创作工艺本身，以及怎么把音乐意图写成能被生成引擎正确执行的音乐 prompt。

以下都是指南，不是铁律。艺术本就会刻意打破规则——服务于歌，而非服务于清单本身；哪条不服务这首歌，就丢开它。

## 1. 歌曲结构（任选一种或自造）

常见骨架，可混用/改造/整个丢开：

```
ABABCB  主歌/副歌/主歌/副歌/桥段/副歌     （多数流行/摇滚）
AABA    主歌/主歌/桥段/主歌（副歌型叠句）   （爵士标准曲、抒情曲）
ABAB    主歌/副歌交替                      （简单直接）
AAA     主歌/主歌/主歌（无副歌、叙事体）    （民谣、说故事）
```

六个积木：
- **Intro** —— 定调、把听者拉进来
- **Verse（主歌）** —— 故事、细节、世界观铺陈
- **Pre-Chorus（导歌）** —— 可选，副歌前的张力斜坡
- **Chorus（副歌）** —— 情绪核心，被记住的部分
- **Bridge（桥段）** —— 一次绕道，视角或调性的转折
- **Outro** —— 告别，可呼应或颠覆前文

不必六件都用。有些好歌只有一段反复演化的素材。**结构服务情绪，不是反过来。**

## 2. 押韵、格律与声音

**韵型（从紧到松）：**
- 完美韵 Perfect：lean/mean
- 家族韵 Family：crate/braid
- 元音谐音 Assonance：had/glass（元音相同、结尾不同）
- 辅音谐音 Consonance：scene/when（元音不同、结尾相近）
- 近似/斜韵 Near/slant：足以暗示关联但不锁死

混用为佳：全用完美韵容易像儿歌；全用斜韵容易显得敷衍。混合处才是活的。

**内韵**：不只押行尾，行内也押。"We pruned the lies from bleeding trees / Distilled the storm from entropy" —— "lies/flies"、"trees/entropy" 制造行内回声。

**格律（Meter）**：重音与非重音音节的节奏。
- 平行句之间音节数匹配有助于可唱性
- **重音位置比总音节数更重要**
- 念出声——卡壳的地方就是格律要修的地方
- 刻意打破格律可制造强调或意外感

## 3. 情绪动态弧

把一首歌当成一段旅程，而非一条平路。

**能量映射（粗略参考，非硬性规定）：**
```
Intro: 2-3  |  Verse: 5-6  |  Pre-Chorus: 7
Chorus: 8-9  |  Bridge: 视情况  |  Final Chorus: 9-10
```

最强的动态手法是**对比**：
- 尖叫前先耳语，比一路尖叫更有冲击力
- 密集前先稀疏；快前先慢；高前先低
- "落地"之所以有效，是因为前面有铺垫
- **静默本身也是一件乐器**

"耳语→咆哮→耳语"：从亲密开始，推到全力，再退回脆弱。适用于抒情曲、史诗曲、赞歌。

## 4. 写词的手艺

**Show, don't tell（多数情况下）：**
- "我很难过" = 扁平
- "门口挂钩上还留着你的卫衣" = 有生命力
- 但有时候直白地说"我付出我的生命"本身就是力量所在——不是铁律

**Hook（记忆点）：**
- 被记住、被哼唱、被反复念叨的那一句
- 通常是标题或核心短语
- 旋律 + 歌词 + 情绪三者对齐时效果最好
- 放在最该落地的位置（常是副歌的第一句或最后一句）

**Prosody（歌词与音乐互相配合）：**
- 稳定情绪（解决感、平静）配解决式旋律、完美韵、已解决和弦
- 不稳定情绪（渴望、疑虑）配游移旋律、近似韵、未解决和弦
- 主歌旋律通常偏低，副歌走高——但如果服务于歌，可以反过来

**要避免的（除非你是故意为之）：**
- 自动驾驶式的陈词滥调（"heart of gold" 没有铺垫地直接用）
- 为凑韵硬拗语序（"Yoda 式"倒装）
- 每段能量都一样（动态扁平）
- 把初稿当圣旨——修改本身就是创作的一部分

## 5. 改编与仿写（Parody and Adaptation）

用新词改写一首已有歌曲时：

**先画骨架**：映射原曲结构——
- 数每行音节数
- 标出韵式（ABAB、AABB 等）
- 识别哪些音节是**重音**
- 记下长音/延音落在哪里

**填新词对齐骨架：**
- 让重音音节对齐原曲同样的拍点
- 总音节数可有 1-2 个非重音音节的浮动空间
- 长音处尽量匹配原曲的**元音音**（原曲长音是 "LOOOVE" 的 "oo" 音，"FOOOD" 比 "LIFE" 更贴合）
- 单音节位置的换词是保节奏最干净的手法（Crime → Code、Snake → Noose）
- 把新词唱到原曲旋律上——卡壳就改

**概念（Concept）：**
- 选一个足以撑起整首歌的概念
- 从标题/Hook 出发向外搭建
- 先大量发想原料（双关、短语、意象），再挑最好的填进结构
- 若某处必须落一句特定台词，可反向从韵式倒推搭建前文

**保留少量原句**：留几句原曲的台词或结构完整不改，能增加辨识度，让听者感受到与原曲的连接。

## 6. 写音乐 Prompt（交给 `generate_audio` · 音乐生成）

### 风格/流派描述字段

**公式（按需调整）：** 流派 + 情绪 + 年代 + 乐器 + 人声特征 + 制作质感 + 动态

```
差：  "悲伤摇滚歌曲"
好：  "电影感管弦乐间谍惊悚风，1960 年代冷战时期，烟熏性感女声，
       大乐队爵士，铜管声部（小号+法国号），恢弘弦乐，小调，
       复古模拟温暖质感"
```

**描述"旅程"，而非只列流派：**
```
"以幽灵般的耳语声、稀疏钢琴开场。逐渐叠入弱音铜管。
 副歌处推向全编制管弦乐。第二段主歌以原始咆哮式强唱爆发。
 尾奏收回到孤单钢琴与脆弱耳语，渐弱至寂静。"
```

**要点：**
- 风格字段可以写得较长——把预算都用在描述"旅程"上，不要只堆流派词
- **不得出现知名音乐人姓名或商标**——描述声音本身，而非引用作品/艺人
  - 用 "1960 年代冷战谍战铜管" 而非某具体电影配乐师风格名
  - 用 "90 年代油渍摇滚（grunge）" 而非某具体乐队名
- 有偏好时明确写出 BPM 与调性
- 用"排除风格"类描述说明你**不**要什么
- 反直觉的流派组合常能出彩："bossa nova + trap"、"阿巴拉契亚哥特"、"chiptune 爵士"
- 建一个**人声人设（persona）**，而不只是给性别："一位饱经风霜的驻唱歌手，烟嗓带沙哑，从脆弱起唱、逐渐推向毁灭性的爆发力"

### Metatags（放在歌词字段的方括号内 `[标签]`）

**结构类：**
`[Intro] [Verse] [Verse 1] [Pre-Chorus] [Chorus] [Post-Chorus] [Hook] [Bridge] [Interlude] [Instrumental] [Instrumental Break] [Guitar Solo] [Breakdown] [Build-up] [Outro] [Silence] [End]`

**演唱表现类：**
`[Whispered] [Spoken Word] [Belted] [Falsetto] [Powerful] [Soulful] [Raspy] [Breathy] [Smooth] [Gritty] [Staccato] [Legato] [Vibrato] [Melismatic] [Harmonies] [Choir] [Harmonized Chorus]`

**动态类：**
`[High Energy] [Low Energy] [Building Energy] [Explosive] [Emotional Climax] [Gradual swell] [Orchestral swell] [Quiet arrangement] [Falling tension] [Slow Down]`

**性别类：**
`[Female Vocals] [Male Vocals]`

**氛围类：**
`[Melancholic] [Euphoric] [Nostalgic] [Aggressive] [Dreamy] [Intimate] [Dark Atmosphere]`

**音效类：**
`[Vinyl Crackle] [Rain] [Applause] [Static] [Thunder]`

**使用规则：**
- 标签同时放风格字段和歌词字段两处，互相强化
- 每段最多 5-8 个标签——太多会让引擎困惑
- 不要自相矛盾（同一段落里不要同时 `[Calm]` 又 `[Aggressive]`）

### 分离风格/歌词的创作模式

- 正式创作请始终使用"分离 Style + Lyrics"的模式（而非单栏简易模式）
- 歌词字段容量上限大致在 ~3,000 字符（约 40-60 行）以内规划
- 务必加结构标签——没有结构标签时引擎会默认退化成平铺的主歌/副歌/主歌、没有情绪弧

## 7. AI 歌手的咬字技巧（Phonetic Tricks）

AI 人声模型不是"读"字，是"发音"字——要主动引导它：

**按读音拼写：**
- 按实际发音重新拼写词语（如 "through" → "thru"）
- 专有名词失败率最高——务必提前小段测试
- 用近音词强制正确发音（如把易错的词换成同音但更易读对的拼法）
- 用连字符引导音节切分（如 "Re-search"、"bio-engineering"）

**演唱控制：**
- 全大写 = 更响、更强烈
- 元音拉长（"lo-o-o-ove"）= 延音/花腔（melisma）
- 省略号（"I... need... you"）= 戏剧性停顿
- 连字符拉伸（"ne-e-ed"）= 情感延展

**始终注意：**
- 数字拼写成文字（"24/7" → "twenty four seven"）
- 缩写词加空格分开字母（"AI" → "A I" 或 "A-I"）
- 专有名词/生僻词先用一段 30 秒左右的短片单独测试
- **一旦生成，发音已经定型**——要改先改歌词文本再重新生成，而非事后修正

## 8. 创作工作流

1. 先写概念/Hook——这首歌的情绪核心是什么？
2. 若是改编，先映射原曲结构（音节、韵式、重音）
3. 自由发想原料——先不设结构地头脑风暴
4. 把词填进结构草稿
5. 念/唱出声——抓卡壳的地方，修格律
6. 写 Suno 风格描述——把动态旅程画出来
7. 给歌词加 metatags 做演唱指导
8. 至少生成 3-5 个版本——当成"录音 take"来对待
9. 挑最好的一版，用续写/延展功能在有潜力的段落上继续build
10. 若无意中出现了神来之笔，留下它

**预期心理准备**：大约每 3-5 次生成才出一个满意结果。反复修改是常态。风格在续写/延展中会漂移——续写时要重新申明流派/情绪。

## 9. 经验教训（Lessons Learned）

- 在风格字段里描述**动态弧**（"耳语→咆哮→耳语"）比单纯堆流派词重要得多——它相当于给引擎一张"演唱地图"。
- 仿写时保留几句原词能增加辨识度和情感重量——听众能感受到原曲的"幽灵"还在。
- 桥段（Bridge）是转换意象的最佳位置：把原曲具体指代换成你主题的隐喻，同时保留其情感功能（反思/转折/顿悟）。
- Hook/标签处的单音节替换是既保持节奏又改变含义的最干净手法。
- 一段强有力的人声人设描述，比任何单个 metatag 都更能左右效果。
- 不要拘泥于规则本身。如果某一句打破了格律但打动人心，就留着它——**感觉才是本体，工艺服务于艺术，而非反过来**。

## 工具适配说明

最终音乐生成统一走本环境的 `generate_audio`（音乐）；本 skill 交付的是写给它的音乐 prompt（风格描述 + 结构化歌词/metatags），不涉及具体平台 UI 操作（如某平台的字数上限、"排除风格"输入框等属该平台运维细节，非创作工艺，不在本 skill 范围内——工艺本身与平台无关，照常适用）。歌名/艺人名/商标类规则维持源意图：不得在音乐 prompt 中出现知名音乐人姓名或商标，一律描述声音本身。

按 SP：视频片段不内嵌 BGM，音乐由 `generate_audio` 单独生成，合成阶段混音。

## 边界（差异说明，非依赖）

阿拉伯语歌词咬字/注音的专门深化 → `arabic-tashkeel-suno`；卡点配乐/与已有画面时间线对齐 → `soundtrack-composer`。本 skill 是通用词曲创作 + 音乐 prompt 工艺的单一真源，以上均为场景差异导航，非依赖，本 skill 自足。
