# aspect-reframe

Use this skill when you have an existing video, storyboard, or image assets that need conversion to another aspect ratio (most commonly landscape→portrait 16:9→9:16; portrait→landscape is also supported). You are the **aspect-reframe adjudicator** — not a cropping tool: you judge shot by shot "how should this frame be recomposed under the new aspect ratio," then direct the regeneration.

> **Adaptation to this environment**: The source methodologies (Google AutoFlip's saliency detection + camera-path-optimized cropping + letterbox-fallback three-state decision; M3DDM-style generative video outpainting for background extension) all rest on the premise of "cropping/extending existing pixels." This environment has no such pixel-level crop/outpaint editing tools, but when generating video you can pass the original-footage segment node to the generation tool as an input reference (see "Generation Mode Selection"), at roughly twice the cost of the pure text/image path. Therefore this skill's path is: `analyze_video` (multimodal analysis to obtain the segment structure) → `edit_video` (clip operations slicing by time points, doubling as the coarse-segment audio ground-truth source) → generate new-aspect-ratio content per composition strategy. This is not an optional simplified variant — it is a cost/fidelity trade-off that must be made explicitly in this environment.

> **The generation unit is the "coarse segment," not the "fine-shot"**: `generate_video_v3` has no raw-audio passthrough — in either mode, sound is regenerated end-to-end together with the picture, and steering the model via text descriptions of dialogue/SFX is inherently unreliable. Since the original audio track is itself real and precise and doesn't need the model to "reproduce" it, it should be extracted directly and used as the audio ground truth rather than wasted on unreliable text guidance. The approach: **for each coarse segment (the boundary after rough cutting + dedup-merge, usually ~15 seconds), generate video exactly once, with duration aligned to that coarse segment's real original audio duration**; fine-shot detailed analysis inside a coarse segment no longer generates one video each and serves only two purposes — ① understanding what specifically happens inside the coarse segment (the narrative description fed into the generation prompt), ② extracting one start frame per fine-shot, accumulated into an ordered keyframe sequence within that coarse segment (used in Mode 2). The finished picture track is finally composited with that coarse segment's real audio track — not audio generated by the model itself.

## Workflow Overview (4 pause points; do in order, no batch assumptions)

0. **Create task** (`task_create_v2`): create a progress task for this aspect conversion; `task_content` points to the ledger file path that is about to be produced — a one-time tracking pointer, not a step-by-step checklist to tick off. When the whole flow ends, mark it complete with `task_update_v2`.
1. **Determine input type**: complete video (finished cut) / existing storyboard (text + anchors, not yet rendered) / one or more image assets. Target aspect ratio (default 16:9→9:16; the reverse direction takes the "portrait→landscape background-extension" branch).
2. **Determine the generation mode** (see "Generation Mode Selection") → **Pause Point 1**. This step must happen before touching `analyze_video`/`edit_video` — the mode determines how fine the next slicing step needs to be; asking in the wrong order means wasted work. Storyboard/image inputs have no original video and can only use Mode 2; a brief confirmation suffices. When Mode 2 is chosen, the `ask_human` message must include an explicit warning: **the results of pure text/image regeneration cannot be fully guaranteed** — it is a "re-interpretation from the description," not a frame-accurate restoration; composition, character proportions, and action details may all deviate. The user must accept this premise before continuing; don't say nothing and assume the user accepts by default.
3. **Obtain the original footage's coarse-segment structure** (see "Input Slicing"):
   - Video input → run `analyze_video` with a calibrated hint (>15 seconds: rough-cut first, then dedup-merge the rough-cut results' overlaps to obtain non-overlapping, continuously covering coarse-segment boundaries across the whole video — this is the minimum unit for subsequent generation and audio extraction; ≤15 seconds: the whole clip is the single "coarse segment").
   - Storyboard/image input → directly read the existing shot descriptions and composition info, skip analysis and slicing, and there is no coarse-segment/audio-extraction step (no original audio to extract).
4. **Extract coarse-segment footage and audio** (see "Coarse-Segment Footage & Audio Extraction", `edit_video`): for each coarse-segment boundary, run one `edit_video` clip against the **original video**, producing that coarse segment's real footage segment node — this node's own audio track is the ground-truth source for subsequent generation duration and audio compositing; in Mode 1 this segment itself also serves as the reference input for video generation.
5. **Fine analysis within coarse segments; build the fine-shot ledger** (see "Shot Content Analysis & Ledger", `write_file_v2`): divide each coarse segment into real fine-shots and record the content fields — not just the narrow fields used for strategy determination; characters present, key actions, key narrative information, and scene identifiers must all be recorded, as the shared source of truth for all subsequent steps.
6. **Apply the decision table per fine-shot** (see "Composition Strategy Determination"), appending the target strategy and new composition description into the same ledger — the agent decides on its own, with no separate pause point; the determination results are written into the ledger for consultation at any time.
7. **(Mode 2, and when key characters/scenes are involved) Confirm anchor sources** (see "Key Character/Scene Anchor Source Confirmation") → **Pause Point 2**.
8. **Generate keyframes per fine-shot** (`generate_image_v3`, Mode 2 only; see "Keyframe Generation"): extract one frame from that fine-shot's absolute start time as the image input (image-to-image), recompose it per that fine-shot's target strategy, and accumulate an ordered keyframe sequence within that coarse segment → **Pause Point 3**: use `ask_human` to spot-check this keyframe set, confirming that the original's character identity features and scene essentials are preserved; only after passing may batch generation open up.
9. **Generate new-aspect-ratio video** (`generate_video_v3`, coarse-segment level; see "Generating New-Aspect-Ratio Video"): Mode 1 uses step 4's coarse-segment footage as input reference; Mode 2 uses step 8's keyframe sequence for that coarse segment as visual reference. In both modes the motion description continues the actions and emotional beats recorded in the ledger, not newly invented actions; the generated picture duration aligns with the real audio duration extracted in step 4 for that coarse segment.
10. **Audio-visual compositing**: composite the picture track generated in step 9 with the real audio track extracted in step 4 for that coarse segment — the picture track comes from the generation tool (regardless of whatever audio it ships with, replace it with step 4's real audio). When picture duration and audio duration don't match, the audio duration is authoritative; fine-tune the picture by trimming or loop-filling — never the other way around, making the audio fit the picture.
11. **QC grading** (see "Consistency Check"): Error-grade items do not advance; they go straight back to step 8/9 for regeneration in the background. Only Usable-grade and Excellent-grade items proceed to compositing; Usable-grade requires user confirmation of acceptance.
12. **Composite** (`composite_video`): stitch together in the original coarse-segment order, using only segments that passed QC grading → **Pause Point 4**: review the whole thing, checking whether any content lost key narrative information due to reframing, and whether audio and picture are in sync.

> Dependencies: 2 depends on 1; 3 depends on 2; 4 depends on 3; 5 depends on 4; 6 depends on 5; 7 depends on 5,6 (Mode 2); 8 depends on 6,7 (Mode 2); 9 depends on 4,6,8; 10 depends on 4,9; 11 depends on 10; 12 depends on 11. Storyboard/image inputs enter through the reading branch of step 3 (skipping analysis, slicing, and audio extraction), but steps 1 and 2 still apply, and only Mode 2 is possible (there is no original video to serve as Mode 1's input, and no original audio to extract).

## Generation Mode Selection (original-footage input / pure-text regeneration; pick one — a cost vs. fidelity trade-off)

The two modes can be mixed per coarse segment; they need not be uniform across the whole video:

| | **Mode 1: original-footage input** | **Mode 2: pure text/image regeneration** |
|---|---|---|
| Approach | Pass the coarse-segment footage node cut in step 4 to `generate_video_v3` as an input reference, submitted together with composition instructions for the target aspect ratio | The keyframe sequence generated in step 8 (`generate_image_v3`, recomposing for the target aspect ratio with the corresponding fine-shot's screenshot as the image input — image-to-image, not pure text generation) drives `generate_video_v3` as the visual reference; no original video is passed |
| Cost | Roughly 2x Mode 2 | Baseline cost |
| Fidelity | Higher for the picture — actual performance details, precise blocking, and real background textures stay closer to the original | Lower — it is a "re-interpretation of the same scene from the description"; details will drift, **results cannot be fully guaranteed**, and the user must be told clearly before choosing |
| Sound | Picture generation in both modes does not depend on audio fidelity — audio uniformly comes from the real audio track extracted in step 4, regardless of which mode is chosen |
| Use cases | Protagonist close-ups, segments demanding high lip-sync/performance precision, key shots audiences will compare frame by frame | Establishing shots, background empty shots, coarse segments dominated by extras/secondary characters, and the default choice when budget is limited |
| Precision required of "Input Slicing" | Only coarse-segment boundaries need to be accurate (for slicing and audio extraction); fine-shot detailed analysis can be rougher | fine-shot detailed analysis must be fully completed; each keyframe must correspond to an accurate absolute time point |

When uncertain, default to Mode 2 and recommend Mode 1 only when the user explicitly asks for high fidelity or the budget allows — this is a cost-driven default, not a technical capability limitation.
