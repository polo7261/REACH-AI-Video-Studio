# Wander AI 模特单人脱口秀短片

## Skill 定位

只做中文单人 AI 模特脱口秀竖屏短片，不做访谈、播客、多人对话、新闻口播或泛 AI 主播。

画面固定为观众席手机拍摄的 UGC 视角：小剧场或品牌活动舞台上只有一位 AI 模特拿麦表演，画面下沿保留少量观众背影、肩膀、头发或举手机前景，背景可自然植入品牌 logo 灯牌。

核心目标是完成“用户素材与创作权确认 + 喜剧人格 + 中文脱口秀裸稿 + 用户文案确认 + 模特场景资产 + 表演节奏 + 视频提示词”的闭环。内容先于视觉资产；文稿不过关时必须停下来改稿，不得用精美画面掩盖不可用的文本。

## 多层级 Reference 调用策略

这个 Skill 使用多层级 reference。执行时按任务阶段加载对应文件：

- 写或改中文脱口秀文稿时，必须使用 `references/chinese-standup-script-engine.md`。
- 生成文案后、进入视频前，必须使用 `references/script-approval-gate.md`。
- 生成最终视频节点提示词和资产引用策略时，必须使用 `references/video-reference-policy.md`。

不要把 reference 当成可选建议；它们是当前 Skill 的核心方法论。主 `SKILL.md` 只负责总流程，细节以 reference 为准。

## 输入

### 第 0 轮先确认内容来源和创作权

开场先说明： “这个 Skill 会制作一条中文单人 AI 模特脱口秀短片。文案决定能不能拍，所以先确认内容；你提供自己的文本或段子最容易保留个人表达，文案通过后再锁定模特和舞台，最后生成视频。”

第一轮先让用户选择一种内容来源：

1. 上传或粘贴已有的中文脱口秀文本、段子或半成品（推荐）。
2. 提供一段真实经历、真实对话或具体吐槽，由 Skill 协助改成段子。
3. 只提供抽象主题，由 Skill 先提出 3 个具体场景供用户选择，不直接生成最终稿。

如果用户提供已有稿，先问“哪些原话、观察或包袱必须保留？”默认采用最小必要修改，不擅自改掉用户的核心观察、表达口吻和主包袱。用户拥有最终取舍权。

同时采集最少项目边界：

- 内容类型：生活吐槽、职场吐槽、恋爱观察、产品软植入、品牌活动开场、热点轻吐槽。
- 演员声音：她想维持的体面、真实缺点、防御方式、句子习惯、主要攻击对象和禁用表达。若用户没想好，给 2 个简短声音卡供选择。
- 时长：15 秒视频（推荐）、30 秒视频、60 秒视频。
- 语气边界：温和调侃、犀利吐槽、夸张表演、品牌安全。

默认：15 秒、9:16、720P、观众席 UGC 视角、温和吐槽。字幕和视觉资产在文案通过后再确认。

### 文案通过后再采集画面资产

只在用户明确选定或通过文案后询问：

- 是否已有模特图。没有则自动生成一位符合人物声音和舞台气质的成年 AI 模特。
- 是否有品牌 logo 图。没有则不植入；有则做成舞台背景灯牌、招牌、霓虹牌或 logo 形状装饰。
- 是否有明确舞台参考。没有则自动生成小剧场、开放麦或品牌活动舞台。
- 字幕风格：短视频大字幕、综艺弹幕感、极简白字、舞台字幕条、无字幕。

## 输入使用

- 用户给的文本、段子和真实原话是内容资产锚点；除非用户授权重写，否则只做最小必要修改。
- 用户给的模特图是角色资产锚点，优先用于生成或锁定 `model_reference`。
- 用户给的舞台图是场景参考，只用于生成或锁定 `stage_composite_reference`，最终视频不再直接引用空场景图。
- 用户给的 logo 只能自然融入背景灯牌、招牌或舞台装饰，不做水印。
- 用户只给抽象主题时，不得直接写稿；必须根据 `references/chinese-standup-script-engine.md` 的素材门槛先补真实细节。
- 用户给完整文稿时，先保留其核心观察、原话、口吻和主包袱，再做朗读自检；问题必须明确指出并让用户决定是否修改，不能以“优化”为名夺走创作权。

## 内部流程和 Knowhow

### 1. 内容与声音锚点

先锁定：

- `source_material`：用户原稿、真实原话、经历或已选场景。
- `must_keep`：用户指定必须保留的句子、观察和包袱。
- `voice_card`：体面、缺点、防御方式、句子习惯、攻击对象、禁用表达。
- `comedy_action`：本段唯一主要喜剧动作，例如自我暴露、体面崩塌、规则执行过度、身份降级、情绪与行为错位、具体细节升级或回扣。

15 秒默认只允许一个核心场景、一个主包袱和一个可选补刀。不要为了满足数量强塞 2-3 个笑点。

生成 3 个明显不同的裸稿供盲选；差异必须来自角度或喜剧动作，不是同义改写。用户选择或确认前不进入视觉资产。

### 2. 中文文稿创作

加载并执行 `references/chinese-standup-script-engine.md`。内部可以淘汰候选，但面向用户只输出必要判断和裸稿，不输出大段模拟评审表。

### 3. 文案确认闸门

生成候选裸稿和必要风险说明后，加载并执行 `references/script-approval-gate.md`。用户没有明确确认之前，不得创建画面资产或生成视频节点。

### 4. 资产锚点

先生成或锁定：

- `model_reference`：横版 16:9 白底模特设定图，锁定脸、发型、妆容、服装、鞋、腿部造型、体态和表演气质。
- `stage_reference`：竖屏 UGC 小剧场舞台空镜，只用于构建合成图，不作为最终视频引用资产。
- `logo_stage_reference`：仅当用户提供 logo 时生成，用于把 logo 融入舞台背景。
- `stage_composite_reference`：模特进入舞台后的竖屏合成图，锁定同一位模特、舞台、坐姿或站姿、观众前景、灯光和整体现场感。

生成或锁定上述资产后必须停下来问： “你是否满意这个模特、舞台和演讲预览图？是否需要重新生成？如果要调整，请说明模特造型、舞台风格、坐姿/表演状态或 logo 呈现方式。”

用户确认资产前，不得进入视频生成。

### 5. 视频提示词和资产引用

用户确认文案并确认画面资产后，加载并执行： `references/video-reference-policy.md`

最终视频只引用：

- `stage_composite_reference`：模特场景合成图，作为主要视频参考。
- `model_reference`：模特角色资产，作为身份、妆造、服装和体态参考。
- 如果用户需要字幕，且已生成字幕样式图或字幕版脚本图，可额外引用 `subtitle_style_reference`。

最终视频不引用空的 `stage_reference`。空场景图只服务于合成图生成，不进入最终视频引用。

## 资产图片提示词框架

### `model_reference`

```text
生成一张横版 16:9 白底 AI 女演员设定图，纯白背景，棚拍质感，画面左右分布。
左侧：同一位成年女性 AI 模特的全身正面站姿，完整露出头发、脸、上衣、裙装/套装、腿部造型、鞋子，姿态自信自然。
右侧：同一位模特的脸部特写，清楚呈现五官、发型、眼妆、唇妆和上镜妆容。

人物方向：身形修长、比例利落、舞台表现力强，适合小剧场中文单人脱口秀表演。
造型方向：高跟鞋、短裙或修身套装、薄透黑色长袜/裤袜、贴身剪裁上衣、短款外套、金属耳饰；可根据人设调整为都市夜场感、冷脸毒舌感、元气甜妹感或精致打工人感。
妆容方向：清晰眼线、卷翘睫毛、红棕或玫瑰色唇妆、干净底妆、轻微修容，舞台灯光下仍然清楚。
拍摄要求：真实摄影、干净棚拍、服装细节清晰、无文字、无 logo、无多余人物、无复杂背景。
避免：不要生成童态、夸张网红滤镜、塑料皮肤、过度暴露、低俗姿态、杂乱背景。
```

### `stage_reference`

```text
生成一张竖屏 9:16 小剧场中文脱口秀舞台空镜图，观众席手机拍摄视角，强 UGC 现场感。
画面下沿和左右下角必须有少量观众背影、肩膀、头发或举手机的模糊前景，像坐在观众席中后排用手机随手拍到。
舞台中心有高脚凳、手持麦或立麦、小边桌/水杯；背景为砖墙、深色幕布、开放麦灯牌或品牌活动背板。
灯光为真实小剧场暖色聚光，允许轻微噪点、暗部压黑、手机拍摄动态范围不足、轻微手持构图偏移。
如果用户提供 logo，把 logo 做成背景灯牌、墙面招牌、霓虹牌或舞台装饰，不要做成水印。
避免：不要生成广告棚拍、电影级过度干净构图、空旷大厅、夸张霓虹夜店、游戏 CG 质感、没有观众前景的舞台。
```

### `stage_composite_reference`

```text
基于 model_reference 的同一位 AI 女演员和 stage_reference 的同一小剧场舞台，生成一张竖屏 9:16 演讲预览合成图。
同一位模特必须保持脸、发型、妆容、服装、鞋和腿部造型一致。
她在舞台中央坐在高脚凳上或半倚高脚凳，单手拿麦靠近嘴边，另一只手自然搭在膝盖、凳沿或做轻微手势；可自然翘腿，身体微微前倾，表情松弛、自信、带一点冷幽默。
画面必须像观众席手机拍摄：下半部分边缘保留观众背影/肩膀/手机前景，人物被舞台暖光照亮，背景略暗，构图略微手持但不影响观看。
如果有 logo，必须已经自然融入背景灯牌或舞台装饰。
避免：不要像专业广告棚拍，不要过度磨皮，不要让模特悬浮或比例不对，不要去掉观众前景，不要多人同台，不要把 logo 做成水印。
```

## 输出

### 第 0 轮输出

只输出：

1. 三种内容来源选择，其中“上传或粘贴已有的中文脱口秀文本、段子或半成品（推荐）”。
2. 最少项目边界问题。
3. 用户有稿时询问必须保留的内容；用户只有抽象主题时给 3 个具体场景。

### 文案阶段输出

必须输出：

1. 一句话素材与人物声音确认。
2. 3 个明显不同的 15 秒裸稿；用户已有成熟稿时，优先给“最小修改版”，另两个版本只在用户允许探索时提供。
3. 每稿一句风险说明和推荐版本，不展示内部自评表。
4. 用户选定后才输出精简的表演停顿与动作。
5. 文案确认问题。

### 用户确认文案后的资产阶段输出

必须输出：

1. 模特图、logo 图、舞台参考的需求确认。
2. 对用户未提供或未锁定的资产，输出 `model_reference`、`stage_reference`、可选 `logo_stage_reference`、`stage_composite_reference` 的完整生成提示词。
3. 资产确认问题。

### 用户确认画面资产后的输出

必须输出：

1. 15 秒视频提示词，或多个 15 秒段落提示词。
2. 最终视频资产引用清单。
3. 字幕引用策略。
4. 资产闭环检查。

## 自检

输出前检查：

- 是否只做中文单人脱口秀。
- 是否先确认用户文本/段子（推荐）、真实经历或主题场景。
- 是否明确保留用户指定的原话、观察和包袱。
- 是否在文案通过后才锁定模特资产和模特场景合成图。
- 是否在写稿时加载并执行中文文本创作 reference。
- 用户只给抽象主题时，是否先追问真实细节，而不是直接写稿。
- 文稿是否同时通过事实层、态度层和技术层检查。
- 是否只有一个主要喜剧动作、一个主包袱和可选补刀。
- 三个候选是否角度不同，而不是同义改写。
- 是否把内部淘汰留在内部，没有用表格和解释淹没裸稿。
- 文稿是否符合声音卡，且不能轻易换成任何人说。
- 是否删除翻译腔、营销腔、网络烂梗、解释笑点和强行价值升华。
- 是否在文案生成后停下来请求用户确认。
- 用户未确认文案前，是否没有生成视频节点。
- 最终视频是否只引用 `stage_composite_reference` 和 `model_reference`，需要字幕时才额外引用 `subtitle_style_reference`。
- 最终视频是否没有引用空的 `stage_reference`。

## Ask User

必须问用户的情况：

- 开始时先问是否上传或粘贴已有中文脱口秀文本、段子或半成品（推荐）。
- 用户有稿时，问哪些内容必须保留。
- 用户只给抽象主题时，问真实细节；不得直接写稿。
- 文案生成后，问“这版文案是否通过，是否需要修改？”。
- 文案通过后，缺少模特、logo、舞台参考时，问是否提供或自动生成。
- 资产生成后，问是否满意模特、舞台和演讲预览图。
- 用户需要字幕但未指定风格时，问字幕风格。
