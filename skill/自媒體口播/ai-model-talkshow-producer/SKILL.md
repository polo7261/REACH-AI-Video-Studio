# Wander AI 模特單人脫口秀短片

## Skill 定位

只做中文單人 AI 模特脫口秀豎屏短片，不做訪談、播客、多人對話、新聞口播或泛 AI 主播。

畫面固定為觀眾席手機拍攝的 UGC 視角：小劇場或品牌活動舞臺上只有一位 AI 模特拿麥表演，畫面下沿保留少量觀眾背影、肩膀、頭髮或舉手機前景，背景可自然植入品牌 logo 燈牌。

核心目標是完成“使用者素材與創作權確認 + 喜劇人格 + 中文脫口秀裸稿 + 使用者文案確認 + 模特場景資產 + 表演節奏 + 影片提示詞”的閉環。內容先於視覺資產；文稿不過關時必須停下來改稿，不得用精美畫面掩蓋不可用的文字。

## 多層級 Reference 呼叫策略

這個 Skill 使用多層級 reference。執行時按任務階段載入對應檔案：

- 寫或改中文脫口秀文稿時，必須使用 `references/chinese-standup-script-engine.md`。
- 生成文案後、進入影片前，必須使用 `references/script-approval-gate.md`。
- 生成最終影片節點提示詞和資產引用策略時，必須使用 `references/video-reference-policy.md`。

不要把 reference 當成可選建議；它們是當前 Skill 的核心方法論。主 `SKILL.md` 只負責總流程，細節以 reference 為準。

## 輸入

### 第 0 輪先確認內容來源和創作權

開場先說明： “這個 Skill 會製作一條中文單人 AI 模特脫口秀短片。文案決定能不能拍，所以先確認內容；你提供自己的文字或段子最容易保留個人表達，文案透過後再鎖定模特和舞臺，最後生成影片。”

第一輪先讓使用者選擇一種內容來源：

1. 上傳或貼上已有的中文脫口秀文字、段子或半成品（推薦）。
2. 提供一段真實經歷、真實對話或具體吐槽，由 Skill 協助改成段子。
3. 只提供抽象主題，由 Skill 先提出 3 個具體場景供使用者選擇，不直接生成最終稿。

如果使用者提供已有稿，先問“哪些原話、觀察或包袱必須保留？”預設採用最小必要修改，不擅自改掉使用者的核心觀察、表達口吻和主包袱。使用者擁有最終取捨權。

同時採集最少專案邊界：

- 內容型別：生活吐槽、職場吐槽、戀愛觀察、產品軟植入、品牌活動開場、熱點輕吐槽。
- 演員聲音：她想維持的體面、真實缺點、防禦方式、句子習慣、主要攻擊物件和禁用表達。若使用者沒想好，給 2 個簡短聲音卡供選擇。
- 時長：15 秒影片（推薦）、30 秒影片、60 秒影片。
- 語氣邊界：溫和調侃、犀利吐槽、誇張表演、品牌安全。

預設：15 秒、9:16、720P、觀眾席 UGC 視角、溫和吐槽。字幕和視覺資產在文案透過後再確認。

### 文案透過後再採集畫面資產

只在使用者明確選定或透過文案後詢問：

- 是否已有模特圖。沒有則自動生成一位符合人物聲音和舞臺氣質的成年 AI 模特。
- 是否有品牌 logo 圖。沒有則不植入；有則做成舞臺背景燈牌、招牌、霓虹牌或 logo 形狀裝飾。
- 是否有明確舞臺參考。沒有則自動生成小劇場、開放麥或品牌活動舞臺。
- 字幕風格：短影片大字幕、綜藝彈幕感、極簡白字、舞臺字幕條、無字幕。

## 輸入使用

- 使用者給的文字、段子和真實原話是內容資產錨點；除非使用者授權重寫，否則只做最小必要修改。
- 使用者給的模特圖是角色資產錨點，優先用於生成或鎖定 `model_reference`。
- 使用者給的舞臺圖是場景參考，只用於生成或鎖定 `stage_composite_reference`，最終影片不再直接引用空場景圖。
- 使用者給的 logo 只能自然融入背景燈牌、招牌或舞臺裝飾，不做水印。
- 使用者只給抽象主題時，不得直接寫稿；必須根據 `references/chinese-standup-script-engine.md` 的素材門檻先補真實細節。
- 使用者給完整文稿時，先保留其核心觀察、原話、口吻和主包袱，再做朗讀自檢；問題必須明確指出並讓使用者決定是否修改，不能以“最佳化”為名奪走創作權。

## 內部流程和 Knowhow

### 1. 內容與聲音錨點

先鎖定：

- `source_material`：使用者原稿、真實原話、經歷或已選場景。
- `must_keep`：使用者指定必須保留的句子、觀察和包袱。
- `voice_card`：體面、缺點、防禦方式、句子習慣、攻擊物件、禁用表達。
- `comedy_action`：本段唯一主要喜劇動作，例如自我暴露、體面崩塌、規則執行過度、身份降級、情緒與行為錯位、具體細節升級或回扣。

15 秒預設只允許一個核心場景、一個主包袱和一個可選補刀。不要為了滿足數量強塞 2-3 個笑點。

生成 3 個明顯不同的裸稿供盲選；差異必須來自角度或喜劇動作，不是同義改寫。使用者選擇或確認前不進入視覺資產。

### 2. 中文文稿創作

載入並執行 `references/chinese-standup-script-engine.md`。內部可以淘汰候選，但面向使用者只輸出必要判斷和裸稿，不輸出大段模擬評審表。

### 3. 文案確認閘門

生成候選裸稿和必要風險說明後，載入並執行 `references/script-approval-gate.md`。使用者沒有明確確認之前，不得建立畫面資產或生成影片節點。

### 4. 資產錨點

先生成或鎖定：

- `model_reference`：橫版 16:9 白底模特設定圖，鎖定臉、髮型、妝容、服裝、鞋、腿部造型、體態和表演氣質。
- `stage_reference`：豎屏 UGC 小劇場舞臺空鏡，只用於構建合成圖，不作為最終影片引用資產。
- `logo_stage_reference`：僅當使用者提供 logo 時生成，用於把 logo 融入舞臺背景。
- `stage_composite_reference`：模特進入舞臺後的豎屏合成圖，鎖定同一位模特、舞臺、坐姿或站姿、觀眾前景、燈光和整體現場感。

生成或鎖定上述資產後必須停下來問： “你是否滿意這個模特、舞臺和演講預覽圖？是否需要重新生成？如果要調整，請說明模特造型、舞臺風格、坐姿/表演狀態或 logo 呈現方式。”

使用者確認資產前，不得進入影片生成。

### 5. 影片提示詞和資產引用

使用者確認文案並確認畫面資產後，載入並執行： `references/video-reference-policy.md`

最終影片只引用：

- `stage_composite_reference`：模特場景合成圖，作為主要影片參考。
- `model_reference`：模特角色資產，作為身份、妝造、服裝和體態參考。
- 如果使用者需要字幕，且已生成字幕樣式圖或字幕版指令碼圖，可額外引用 `subtitle_style_reference`。

最終影片不引用空的 `stage_reference`。空場景圖只服務於合成圖生成，不進入最終影片引用。

## 資產圖片提示詞框架

### `model_reference`

```text
生成一張橫版 16:9 白底 AI 女演員設定圖，純白背景，棚拍質感，畫面左右分佈。
左側：同一位成年女性 AI 模特的全身正面站姿，完整露出頭髮、臉、上衣、裙裝/套裝、腿部造型、鞋子，姿態自信自然。
右側：同一位模特的臉部特寫，清楚呈現五官、髮型、眼妝、唇妝和上鏡妝容。

人物方向：身形修長、比例利落、舞臺表現力強，適合小劇場中文單人脫口秀表演。
造型方向：高跟鞋、短裙或修身套裝、薄透黑色長襪/褲襪、貼身剪裁上衣、短款外套、金屬耳飾；可根據人設調整為都市夜場感、冷臉毒舌感、元氣甜妹感或精緻打工人感。
妝容方向：清晰眼線、捲翹睫毛、紅棕或玫瑰色唇妝、乾淨底妝、輕微修容，舞臺燈光下仍然清楚。
拍攝要求：真實攝影、乾淨棚拍、服裝細節清晰、無文字、無 logo、無多餘人物、無複雜背景。
避免：不要生成童態、誇張網紅濾鏡、塑膠皮膚、過度暴露、低俗姿態、雜亂背景。
```

### `stage_reference`

```text
生成一張豎屏 9:16 小劇場中文脫口秀舞臺空鏡圖，觀眾席手機拍攝視角，強 UGC 現場感。
畫面下沿和左右下角必須有少量觀眾背影、肩膀、頭髮或舉手機的模糊前景，像坐在觀眾席中後排用手機隨手拍到。
舞臺中心有高腳凳、手持麥或立麥、小邊桌/水杯；背景為磚牆、深色幕布、開放麥燈牌或品牌活動背板。
燈光為真實小劇場暖色聚光，允許輕微噪點、暗部壓黑、手機拍攝動態範圍不足、輕微手持構圖偏移。
如果使用者提供 logo，把 logo 做成背景燈牌、牆面招牌、霓虹牌或舞臺裝飾，不要做成水印。
避免：不要生成廣告棚拍、電影級過度乾淨構圖、空曠大廳、誇張霓虹夜店、遊戲 CG 質感、沒有觀眾前景的舞臺。
```

### `stage_composite_reference`

```text
基於 model_reference 的同一位 AI 女演員和 stage_reference 的同一小劇場舞臺，生成一張豎屏 9:16 演講預覽合成圖。
同一位模特必須保持臉、髮型、妝容、服裝、鞋和腿部造型一致。
她在舞臺中央坐在高腳凳上或半倚高腳凳，單手拿麥靠近嘴邊，另一隻手自然搭在膝蓋、凳沿或做輕微手勢；可自然翹腿，身體微微前傾，表情鬆弛、自信、帶一點冷幽默。
畫面必須像觀眾席手機拍攝：下半部分邊緣保留觀眾背影/肩膀/手機前景，人物被舞臺暖光照亮，背景略暗，構圖略微手持但不影響觀看。
如果有 logo，必須已經自然融入背景燈牌或舞臺裝飾。
避免：不要像專業廣告棚拍，不要過度磨皮，不要讓模特懸浮或比例不對，不要去掉觀眾前景，不要多人同臺，不要把 logo 做成水印。
```

## 輸出

### 第 0 輪輸出

只輸出：

1. 三種內容來源選擇，其中“上傳或貼上已有的中文脫口秀文字、段子或半成品（推薦）”。
2. 最少專案邊界問題。
3. 使用者有稿時詢問必須保留的內容；使用者只有抽象主題時給 3 個具體場景。

### 文案階段輸出

必須輸出：

1. 一句話素材與人物聲音確認。
2. 3 個明顯不同的 15 秒裸稿；使用者已有成熟稿時，優先給“最小修改版”，另兩個版本只在使用者允許探索時提供。
3. 每稿一句風險說明和推薦版本，不展示內部自評表。
4. 使用者選定後才輸出精簡的表演停頓與動作。
5. 文案確認問題。

### 使用者確認文案後的資產階段輸出

必須輸出：

1. 模特圖、logo 圖、舞臺參考的需求確認。
2. 對使用者未提供或未鎖定的資產，輸出 `model_reference`、`stage_reference`、可選 `logo_stage_reference`、`stage_composite_reference` 的完整生成提示詞。
3. 資產確認問題。

### 使用者確認畫面資產後的輸出

必須輸出：

1. 15 秒影片提示詞，或多個 15 秒段落提示詞。
2. 最終影片資產引用清單。
3. 字幕引用策略。
4. 資產閉環檢查。

## 自檢

輸出前檢查：

- 是否只做中文單人脫口秀。
- 是否先確認使用者文字/段子（推薦）、真實經歷或主題場景。
- 是否明確保留使用者指定的原話、觀察和包袱。
- 是否在文案透過後才鎖定模特資產和模特場景合成圖。
- 是否在寫稿時載入並執行中文文字創作 reference。
- 使用者只給抽象主題時，是否先追問真實細節，而不是直接寫稿。
- 文稿是否同時透過事實層、態度層和技術層檢查。
- 是否只有一個主要喜劇動作、一個主包袱和可選補刀。
- 三個候選是否角度不同，而不是同義改寫。
- 是否把內部淘汰留在內部，沒有用表格和解釋淹沒裸稿。
- 文稿是否符合聲音卡，且不能輕易換成任何人說。
- 是否刪除翻譯腔、營銷腔、網路爛梗、解釋笑點和強行價值昇華。
- 是否在文案生成後停下來請求使用者確認。
- 使用者未確認文案前，是否沒有生成影片節點。
- 最終影片是否只引用 `stage_composite_reference` 和 `model_reference`，需要字幕時才額外引用 `subtitle_style_reference`。
- 最終影片是否沒有引用空的 `stage_reference`。

## Ask User

必須問使用者的情況：

- 開始時先問是否上傳或貼上已有中文脫口秀文字、段子或半成品（推薦）。
- 使用者有稿時，問哪些內容必須保留。
- 使用者只給抽象主題時，問真實細節；不得直接寫稿。
- 文案生成後，問“這版文案是否透過，是否需要修改？”。
- 文案透過後，缺少模特、logo、舞臺參考時，問是否提供或自動生成。
- 資產生成後，問是否滿意模特、舞臺和演講預覽圖。
- 使用者需要字幕但未指定風格時，問字幕風格。
