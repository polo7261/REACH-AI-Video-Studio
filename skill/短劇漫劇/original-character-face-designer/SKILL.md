# 原創 AI 角色捏臉

## 目標與邊界

從角色用途與視覺意圖出發，設計具有辨識度的原創人物面部，交付可直接複製使用的生圖提示詞，並為後續角色複用保留身份依據。

核心方法：先設計輪廓和比例，再確定識別特徵及五官協調，最後配置表情、妝造、構圖和光線。覆蓋不同年齡、性別外觀與藝術風格；不要把年輕女性、灰底影棚或真人寫實當作所有任務的固定答案。

本 Skill 預設完成角色設計與提示詞編寫。使用者要求生圖時，才使用當前環境實際可用的生成工具；缺少工具時交付提示詞，不聲稱已經生成、檢查或儲存圖片。不要僅因使用本 Skill 就啟動批次生圖、購買服務或安裝元件。

## 一、任務判斷與輸入

根據使用者當前意圖選擇工作模式，不要求每次完整重做設計：

| 模式 | 處理方式 |
|---|---|
| 新建角色 | 先與使用者確認角色想法，再分步生成面部圖與（可選）全身像，輸出身份卡與適配提示詞 |
| 修改角色 | 繼承已有身份卡和參考圖，只修改指定部分 |
| 轉換工具 | 保持角色定義，重寫工具相關的表達、輸入欄位和參數 |
| 審看出圖 | 檢視實際圖片，對照要求指出偏差，給出定向修改提示詞 |
| 只要提示詞 | 內部完成必要檢查，直接交付適配後的可複製內容 |

從訊息、已有角色卡和附件中提取以下資訊，不要求使用者逐項填寫：

- 角色用途與身份：短劇人物、虛擬人、品牌角色、漫劇人物等。
- 年齡或年齡感、性別外觀、使用者明確指定的膚色及外觀特點。
- 希望傳達的視覺氣質，以及必須保留或避免的特徵。
- 藝術風格：真人寫實、二維動畫、水墨、三維風格化等。
- 景別、視角、背景、畫幅、表情、妝造、服裝和光線。
- 目標工具、模型或版本、使用入口，以及本次是文生圖還是參考圖編輯。
- 已有角色卡、選定定妝圖及參考圖各自的用途。

處理缺失資訊：

1. 使用者明確要求優先於舊設定；舊設定優先於預設。使用者此次明確改變的專案應更新，不把舊設定當作不可修改的禁令。
2. 不影響核心結果的細節直接補全，並用一句話註明主要假設；不要反覆詢問背景灰度、衣領材質等小項。
3. 年齡、性別外觀或風格的歧義足以導致完全不同的角色時，合併提出一個簡短問題。使用者已授權自由發揮時自行選擇並說明。
4. 未指定工具時預設使用 Seedream 5.5 影像模型，並按本 Skill 的畫幅預設值配置；不阻塞在工具選擇上，也不假定存在負面提示詞欄位。使用者明確指定其他工具或模型時，以使用者指定為準。
5. 沒有既有角色材料時，明確這是新角色草案，不能假裝已繼承某個既有身份。

## 二、新建角色流程（分步確認）

新建角色時按以下順序執行，每一步都要先取得使用者確認再繼續，不要一次性跑完全部步驟。

### 步驟 1：生成前先確認角色想法

第一次生成前，先詢問使用者對這個角色的想法，例如用途、年齡與性別外觀、氣質、風格、造型方向。不要跳過詢問直接出圖。

如果使用者提供的資訊不夠全面，最多提出 3 個問題，每個問題都要給出可選答案，讓使用者直接選擇自己想要生成的人物形象，而不是讓使用者從零描述。問題應聚焦最影響面部結果的專案，例如：

- 年齡感與性別外觀（提供若干具體選項）。
- 藝術風格（真人寫實 / 二維動畫 / 水墨 / 三維風格化等）。
- 主要氣質與識別特徵方向（提供若干具體選項）。

使用者選擇並確認後，才生成人物面部細節圖。面部圖預設 **1:1** 比例（與本 Skill 畫幅預設值一致）。生成後按身份卡格式記錄輪廓、比例、眉眼、鼻部、唇部與識別細節，作為後續複用的身份依據。

### 步驟 2：面部圖滿意後再詢問是否擴展全身像

面部圖生成後，先確認使用者是否滿意：

- 使用者表示滿意時，再詢問是否要擴展生成全身像。不要未經詢問就自動生成全身照。
- 使用者表示不滿意時，按“出圖審看與定向修改”處理，先修正面部圖，不進入全身像環節。

使用者同意生成全身像後，以面部圖作為身份參考，比例預設 **9:16**（與本 Skill 畫幅預設值一致）。全身照提示詞模板如下，保留使用者原句：

```text
保持人物一致性，生成這個人物全身照。這位女性的身高是一米75，體重170斤（偏胖，身材勻稱）。輕鬆愉快地面對鏡頭，站立在拍照。場景不變，保持現在的場景。可以適當改變人物的表情和肢體動作，是自然的狀態下拍出來的一張照片。用徠卡攝影，寫真紀實攝影
```

模板使用說明：

- **可替換佔位項**：性別稱謂（如“這位女性”）、身高體重等體形資料（如“一米75、170斤、偏胖、身材勻稱”）、表情與肢體動作描述、拍攝風格（“徠卡攝影，寫真紀實攝影”）都應按本次角色的實際情況替換，不要照搬示例數值。
- **固定繼承要求**：“保持人物一致性”“場景不變，保持現在的場景”屬於必須保留的固定要求，用於延續已確認的角色身份與場景，不要刪除或改寫。
- 全身照生成後，將結果與面部圖一併納入身份卡與後續複用依據。

## 三、原創設計原則

- 不以特定真人、明星、網紅或已有影視角色的身份相似度作為本 Skill 的設計目標。若使用者要求“像某個人”，說明本 Skill 的原創定位，提煉非身份性的風格、妝造或畫面需求，轉為原創面部設計；不要在輸出中保留該人物姓名作為相似度指令。
- 真人參考圖可以用於提取光線、構圖、髮型類別、妝容和寬泛視覺氣質；不要復刻該人的可識別五官組合。自行設計新角色的輪廓、比例及識別特徵。
- 使用者已有的原創角色圖可以作為同一原創角色的身份參考。區分“外部風格參考”和“原創角色身份參考”，不要因禁止複製真人而禁止複用已選定的原創臉。
- 不從外貌推斷人物真實品性、智力、職業能力或道德。角色氣質是創作意圖，面部結構是視覺選擇，二者沒有必然對應關係。
- “清冷”“親和”“英氣”等詞應落實為可見的輪廓、眼神、姿態和造型；不要僅堆疊“好看、精緻、高階、有故事感”。
- 不把厚唇、高鼻樑、方下頜、明顯顴骨或自然不對稱設為通用缺陷。是否採用取決於角色目標與使用者偏好。
- 不承諾“絕不撞臉”“全球唯一”或“提示詞保證角色一致”。原創設計過程、偶然相似與跨圖穩定性是不同問題，需分別判斷。

## 四、面部設計

### 1. 輪廓與比例

按當前風格選擇有實際作用的結構描述：

- 外輪廓：臉部長寬感、額頭與下頜寬度關係、顴骨轉折、面頰飽滿度。
- 下頜與下巴：轉折位置、線條弧度、下巴長度和寬度。
- 縱向關係：中庭、下庭、鼻部與下巴的相對長度。
- 橫向關係：眼距、眼裂長度、鼻翼與唇部寬度的關係。
- 區域性關係：眉眼距離、眉形走向、面中起伏。

“三庭五眼”只作為描述比例的輔助框架，不作為標準美的硬性指標。優先使用“略短、適中、偏寬”等相對錶達；使用者需要精確比例時可記錄設計目標，但不得聲稱文字能強制模型精確執行或從遮擋圖片測得準確數值。

圓潤輪廓、清晰下頜、長中庭等都可以服務多種角色。允許溫柔眼神與有力量的輪廓共存，也允許成熟人物保留圓眼和飽滿面頰，不自動消除有意設計的反差。

### 2. 識別特徵與五官協調

預設選擇一個主要識別特徵，輔以少量協調特徵，避免所有部位同時被強化。“一個主特徵、兩個輔助”是便於取捨的方法，不是固定配額。

主特徵可以來自輪廓、眉眼、鼻部或唇部，不總是眼睛。寫出具體形態，例如“寬而圓的下巴”“眉尾平直的短眉”“鼻背輕微弧度”“清晰的上唇唇峰”，而非只寫“獨特、有辨識度”。

需要時可加入輕微自然不對稱、雀斑或痣等細節；不要為了原創強行新增疤痕、缺陷或過量裝飾。非必要部位保持協調，不逐項堆滿全部解剖術語。

### 3. 表情、妝造與風格

- 表情與身份分開記錄。親和不必微笑，清冷不必皺眉，反派不必五官誇張；使用者要求微笑時直接採用。
- “不微笑”優先寫成“嘴唇閉合、嘴角平直、面部放鬆”等明確狀態。存在受支援的排除機制時，再補少量對應排除項。
- 髮型、眉毛修飾、妝容、服裝和配飾服務角色用途；換裝或換髮型時，保留約定的固定面部特徵。
- 將天生眉形與化妝修飾區分，避免換妝時無意改變角色身份。
- 寫實風格按需要保留皮膚紋理與年齡細節；二維、水墨和三維風格按各自語言描述，不統一加入毛孔、真實攝影或商業精修。

### 4. 景別與光線

優先用清晰的畫面邊界定義構圖：

| 景別或用途 | 推薦表述 |
|---|---|
| 面部近景 | 包含完整面部，按需求交代是否保留頭頂、下巴和耳部 |
| 胸像 | 頭頂完整入鏡，下沿到上胸，肩頸自然入鏡 |
| 半身 | 明確下沿到腰部或使用者指定位置，避免只寫模糊「半身」 |
| 全身 | 從頭頂到腳底完整入鏡，留出適量邊緣空間 |
| 面部身份基準圖 | 平視、表情中性、面部清晰，避免髮絲和配飾遮擋關鍵輪廓 |

身份基準圖優先讓五官與輪廓可辨；情緒海報、劇情圖可採用使用者需要的暗調、側光或遮擋，不把影棚預設值帶入所有場景。

使用者需要明亮的倫勃朗布光時，描述為：主光來自側前上方，鼻影與面頰陰影銜接，在暗側臉頰眼睛下方留下小面積三角亮區；弱補光保留暗部細節，整體曝光明亮。不要寫成“臉頰出現三角陰影”。左右方向有要求時註明“畫面左側”或“人物自身左側”，避免混淆。

未指定風格和背景、且任務是寫實定妝照時，可以採用“簡潔中性背景、柔和主光、清晰面部、平視胸像”作為可替換預設，並說明該假設。不要因此鎖定女性、年輕化或固定審美。

### 5. 畫幅預設值

未指定畫幅時，按任務型別採用以下預設比例，並在輸出中說明該假設；使用者明確指定畫幅時以使用者指定為準。

- 人臉圖片（面部近景、胸像、面部身份基準圖等以面部為主的畫面）：預設 **1:1**。新建角色流程中生成的面部細節圖同樣預設 1:1。
- 全身照（從頭頂到腳底完整入鏡）：預設 **9:16**。新建角色流程中擴展生成的全身像同樣預設 9:16。

其他景別（如半身）未指定時，可按畫面需要選擇合適比例並說明；不要在使用者已指定畫幅時套用預設值。

## 五、目標生圖工具適配（重點）

### 先確定入口能力，再組織提示詞

工具名稱不等於具體能力。以使用者實際使用的網頁、應用、工作流或 API 為準，確認會影響交付的專案：

- 是否接受完整自然語言，是否有長度限制或提示詞分段約定。
- 是否提供獨立負面欄位，排除機制是否在當前模型及配置下生效。
- 是否支援輸入參考圖、身份參考、影像編輯或多輪延續。
- 畫幅、尺寸、參考強度等是獨立設定、命令參數還是文字要求。

先使用已有會話資訊、當前工具說明或使用者提供的設定；只有涉及不確定的專屬語法、版本相容或欄位時，才查官方資料。不硬編碼“最新版本”、預設模型、參考權重和取樣參數。本 Skill 的預設模型為 Seedream 5.5；使用者未指定工具或模型時按此預設，使用者明確指定其他工具或模型時以使用者指定為準。

不能查證時，用自然語言通用版並說明尚未加入專屬參數。不要虛構負面欄位、參考圖上傳結果、影像 ID、種子、模型版本或功能支援。

### 按實際入口選擇交付方式

| 實際入口 | 提示詞組織 | 排除要求 | 參考圖與參數 |
|---|---|---|---|
| 自然語言對話或單文字輸入 | 用完整句子說明主體、面部、呈現方式和關鍵限制；融入同一文字，優先描述期望狀態 | 不強制另給負面詞框 | 實際支援時說明使用哪張輸入圖及用途；尺寸等按入口提供的欄位填寫 |
| 已確認支援正向與負向欄位 | 正向寫可見特徵，負向單獨交付 | 只保留當前任務相關的少量項，並確認配置未忽略負向條件 | 按當前模型或工作流規則使用設定，不套用其他模型參數 |
| 具有命令參數的入口 | 主體描述與專屬參數按官方語法組合 | 只用已確認相容的排除語法 | 參數放在規定位置；不混入其他平臺語法 |
| 參考圖編輯或同一角色延續 | 明確身份依據、需要保留的特徵和本次變化 | 排除項按該入口能力處理 | 指向實際已提供的原創參考圖；角色編號本身不能替代影像輸入 |
| 未知工具或能力不明 | 輸出中文自然語言通用版，必要限制寫進正文 | 不新增專屬參數，可用一句話提示後續能夠適配 | — |

常見工具的處理原則：

- **Seedream 5.5（預設）**：作為本 Skill 的預設影像模型。按該入口實際提供的欄位處理參考圖、畫幅和排除要求；未指定畫幅時套用本 Skill 的畫幅預設值（人臉 1:1、全身 9:16）。不能僅憑品牌名稱推斷存在負面詞框或身份鎖定功能。
- **ChatGPT / OpenAI 影像入口**：優先交付清晰自然語言指令。需要延續原創角色時，使用入口實際支援的輸入圖或編輯上下文；不要憑空增加獨立負面 API 欄位，或在正文混入其他平臺參數。
- **即夢 / 豆包 / Seedream 等入口**：區分應用與具體 API。根據當前入口實際提供的欄位處理參考圖、尺寸和排除要求；不能僅憑品牌名稱推斷存在負面詞框或身份鎖定功能。
- **Stable Diffusion / SDXL / ComfyUI 等工作流**：明確實際模型和節點如何接收正負條件；“介面有負面輸入框”不等於當前模型配置一定採用它。權重括號、取樣器和參考轉接器（adapter）按工作流核實，不輸出通用神奇參數。
- **FLUX 等模型的不同實現**：不直接繼承其他擴散模型的負向條件、權重語法或參考參數；按實際管線說明適配。
- **Midjourney**：需要排除時可在核實相容性後使用其 `--no` 機制。版本、畫幅及角色參考語法按當前入口核實；沒有必要時不寫版本號，也不把複雜句子機械拆成可能誤排主體的排除詞。

以上是路由原則，不是永久能力清單。使用者切換工具時，重寫輸入形式，但保留已確認的角色身份定義。

### 正文與排除項的寫法

先寫希望畫面出現什麼，再補必要限制。例如“單人胸像，頭頂完整，下沿到上胸，雙唇閉合”通常比重複多輪“不要全身、不要半身太遠、不要微笑”更清晰。

只在當前任務需要時新增排除項，例如：

- 明確不微笑：微笑、露齒笑。
- 明確胸像：全身、腰部以下入鏡。
- 明確寫實：使用者不需要的卡通化處理。
- 明確動畫風：使用者不需要的實拍攝影表現。
- 已見實際問題：多餘人物、重複五官、遮擋關鍵面部的髮絲等。

不維護固定的“通用審美黑名單”，不預設排除厚唇、高鼻樑、方臉、卡通或暗調。把“明星臉、撞臉”寫進負面詞不能驗證原創性；繼續依靠原創設計過程與實際影像審看。

## 六、角色身份卡與複用

新角色交付時給出簡潔身份卡；只要提示詞時可省略展示。身份卡使用明確狀態，區分“草案”和“使用者已選定”，不要將尚未選定的方案自動稱為最終版。

```yaml
角色編號: OC-001
身份版本: v1
狀態: 草案
年齡與性別外觀: 按需求填寫
固定面部:
  輪廓與下頜: 填寫可見形態
  關鍵比例: 填寫少量重要相對關係
  眉眼: 填寫形態、距離和走向
  鼻部: 填寫鼻背與鼻尖形態
  唇部: 填寫唇形與上下唇關係
  膚色與識別細節: 按已知資訊填寫
主要識別特徵: 填寫一項主特徵及必要輔助
可變專案: 表情、髮型、妝容、服裝、姿態、場景、光線、鏡頭
原創身份參考: 未選定；選定後填寫實際檔名或可用影像標識
當前呈現: 記錄本次風格、造型和畫面要求
```

上述 YAML 是內部角色記錄格式，不是任何生圖平臺的 API 參數。交付時填入具體內容，不保留“填寫”“按需求”等佔位文字；未確定專案明確寫“未指定”或“未選定”。

新建角色流程中，面部細節圖確認後填入“固定面部”“主要識別特徵”，並把該圖登記為“原創身份參考”；使用者滿意並擴展生成全身像後，將全身照一併登記為身份參考，並更新“當前呈現”。

複用規則：

1. 使用者選定定妝圖後，將該圖與身份卡一起作為後續依據。僅有提示詞時仍視為文字設定，不能聲稱身份已經鎖定。
2. 換裝、換景和換表情時保留固定面部，提示詞寫清本次變化。不要重新設計未被要求改變的眼型、眼距、鼻形和下巴。
3. 使用者明確改變固定面部特徵時更新身份版本；僅改服裝或背景時更新“當前呈現”，不另造一張臉。
4. 使用多張參考圖時逐張指定作用：身份、服裝、風格或構圖。不能把風格圖的人臉誤當身份參考。
5. 只有實際可用的影像上下文或參考機制才能傳遞圖片身份；“繼續 OC-001”這樣的文字編號只用於管理。
6. 正面、四分之三側面和側面圖僅在使用者需要時擴展，沿用同一身份依據。可以分圖生成後比較，不保證一張多檢視就天然一致。
7. 若參考圖明顯不滿足已確認的身份設定，指出差異；使用者已選定的影像身份優先作為視覺依據，無法調和的關鍵衝突再集中詢問。
8. 跨藝術風格時保留主要識別特徵，並說明風格轉換可能改變特徵的視覺表達；不承諾幾何比例逐畫素不變。

## 七、提示詞編寫與輸出

### 提示詞內容

按任務需要組合以下資訊，不逐段機械填滿：

“生成或編輯目標 → 人物與固定面部 → 表情和當前妝造 → 景別與視角 → 背景、光線與風格 → 必要限制”。

內部設計方法不用原樣寫進提示詞。把“一個強項、兩個輔助”“五官服務人物氣質”等方法改寫為具體形態。相同約束表達一次即可；只有確有必要的重點才重複。

已確認的髮色、服裝等應選定具體值，不在可複製正文裡保留“黑色或棕色”“針織衫或襯衫”等多個未決選項。使用者要求比較方案時才分別給出完整版本。

### 預設交付

新建角色通常輸出：

1. **角色設計摘要**：少量文字說明視覺方向、主識別特徵和主要補全假設。
2. **角色身份卡**：使用上述結構，或等價的緊湊表格。
3. **完整提示詞**：一個可直接複製的程式碼塊，按實際入口組織。
4. **負面提示詞 / 參數**：僅在實際入口支援且任務需要時輸出。獨立欄位分別放入獨立程式碼塊，不混入說明文字。

新建角色時，交付順序與分步確認一致：先確認角色想法，再交付面部圖提示詞（預設 1:1）；使用者滿意並同意擴展後，再交付全身照提示詞（預設 9:16，沿用上文模板並替換佔位項）。

工具未知時預設按 Seedream 5.5 組織提示詞，並標註所用模型與畫幅預設值；不額外製造一個假想負面欄位。目標入口要求整條命令時，給出一條完整可複製命令。

修改任務通常輸出“本次改動與保留項”及完整修改提示詞；身份有變化時再更新身份卡。使用者只要提示詞時，僅輸出可複製內容及不可缺少的輸入圖指引，不追加分析或整張身份卡。

參考圖編輯時，在程式碼塊外說明應附上哪張實際圖片；程式碼塊內用“附上的原創角色定妝圖”等自然稱呼，不捏造平臺影像 ID。圖片尚未提供時，明確該提示詞需配合參考圖使用。

## 八、出圖審看與定向修改

只有使用者提供實際圖片，或生成工具返回可檢視圖片後，才進行視覺驗收。

按任務相關性檢查：

- 使用者硬性要求：年齡感、風格、人數、景別、表情與背景是否符合。
- 身份特徵：輪廓、眉眼、鼻唇關係和識別細節是否延續。
- 可見性與形態：關鍵面部是否被遮擋，五官是否重複或畸變，頭部透視是否異常。
- 呈現質量：寫實皮膚或風格化筆觸是否符合目標，光線是否妨礙辨認。

只報告可觀察的偏差，說明對應修改。例如“下巴比基準圖更窄，需保留較寬的圓下巴”，不要只寫“不像、沒有高階感”。被遮擋或解析度不足的特徵標註“無法判斷”。

每輪優先處理影響身份或使用者要求的少量問題，保留已滿意的部分。支援編輯時優先從選定參考圖定向修改；僅能文生圖時提供完整修訂提示詞，並說明需要重新比較身份。

只有文字時可檢查提示詞衝突和工具相容性，不能宣稱已透過影像驗收。沒有持續重試授權時，不因尚未滿意就自行開啟多輪或批次生成；返回當前結果及下一條可執行修改指令。

新建角色流程中，面部圖未獲使用者滿意前不要進入全身像環節；使用者不滿意時回到本節做定向修改。

## 九、交付前自檢

- 使用者的風格、年齡、性別外觀和構圖有沒有被預設預設覆蓋？
- 固定面部有無互相矛盾的描述？主識別特徵能否落到可見形態？
- 是否把寬泛氣質當成了人物品性的外貌證據？
- 本次輸出是否對應真實入口？是否混入不支援的負面欄位、權重或參數？
- 未指定工具時是否按預設模型 Seedream 5.5 組織輸出，並按任務套用畫幅預設值（人臉 1:1、全身 9:16）？
- 參考圖是否真實存在、用途明確？是否把角色編號誤當身份控制功能？
- 正向與排除項是否互相否定？是否誤排使用者需要的風格或面部特徵？
- 可複製內容是否完整、無未替換佔位符、無互斥選項和多餘方法說明？
- 是否清楚區分設計草案、使用者選定、已生成和已檢視圖片？
- 新建角色時是否先徵得使用者選擇再生成面部圖？
- 是否在使用者滿意後才詢問全身像擴展？

## 十、簡短示例

以下示例展示不同任務的處理方式，面部特徵不應成為其他角色的預設模板。

### 示例 A：預設模型（Seedream 5.5），中年男性寫實角色

使用者：“做一個 45 歲左右的男性修表師，溫和但有主見，白底胸像，不微笑，只要提示詞。”

預設使用 Seedream 5.5，人臉圖片預設 1:1，不附獨立負面欄位：

```text
生成一張原創男性修表師的寫實胸像定妝照，年齡約45歲，純白背景，平視，頭頂完整入鏡，下沿到上胸，面部清楚可辨，畫幅1:1。
臉部外輪廓略寬，下頜轉折圓緩，下巴寬而圓，這是主要識別特徵。中庭比例自然，眼距適中；眉形較平，眼型略長，鼻背輕微弧度，鼻尖圓鈍；上唇略薄、下唇自然飽滿。膚色自然偏暖，保留輕微眼尾細紋和真實皮膚紋理。
短深棕髮夾少量灰髮，穿灰藍色棉質工裝襯衫。雙唇閉合，嘴角平直，眉間放鬆，直視鏡頭，以溫和而專注的眼神表達人物氣質。柔和主光配弱側向陰影，五官與下頜清晰。畫面只有一人，不出現文字、水印或遮臉配飾。
```

### 示例 B：二維水墨女性角色

使用者：“28 歲女性行商，利落、愛笑，水墨動畫，全身白底。入口已確認支援正向和負向欄位。”

正向：

```text
原創成年女性行商，約28歲，二維水墨動畫角色設計，全身站姿，從頭頂到鞋底完整入鏡，純白留白背景，畫幅9:16。
臉型偏長、下頜圓緩，眉毛短而平直、眉尾略向下，這是主要識別特徵；眼距適中，眼型圓而不過大，鼻樑短直，下唇略飽滿。自然微笑，眼神明亮，肩背舒展。
黑髮束成低髮髻，穿赭石色短外衫、米白內衫與深墨色長褲，腰側掛簡潔布袋。以剋制線條和淺墨暈染塑造面部，色彩少而明確，保留手繪筆觸，五官在水墨風格中清楚可辨。
```

負向：

```text
實拍攝影，皮膚毛孔特寫，三維塑膠質感，複雜場景，人物重複，腳部裁切，文字，水印
```

### 示例 C：同一原創角色換裝

使用者：“用剛選定的原創定妝圖，只把上衣換成白襯衫，其餘保持。”

若入口支援圖片編輯，指引使用者附上選定圖，輸出：

```text
編輯附上的原創角色定妝圖，僅將人物上衣替換為簡潔白色棉質襯衫，領口自然，面料褶皺與原圖光線一致。
保留原圖同一人物的面部輪廓、眼型與眼距、鼻形、唇形、膚色和識別細節。保持原有表情、髮型、頭部角度、人物姿態、構圖、光線、背景及畫面風格。衣領與頸部銜接自然，不改變臉部結構。
```

若入口只能文生圖，不把上述編輯能力當成已經可用；改為繼承身份卡的完整文生圖描述，並說明獨立重生成後仍需比較身份。

### 示例 D：新建角色分步確認

使用者：“幫我捏一個原創角色。”

先詢問角色想法；資訊不全面時最多提 3 個帶選項的問題（年齡感與性別外觀、藝術風格、主要氣質方向）。使用者選定後，生成面部細節圖提示詞，預設 1:1。

使用者表示滿意後，再詢問是否擴展全身像。使用者同意時，以面部圖為身份參考，按 9:16 交付全身照提示詞，沿用模板並替換佔位項：

```text
保持人物一致性，生成這個人物全身照。身高一米75，體重170斤（偏胖，身材勻稱）。輕鬆愉快地面對鏡頭，站立在拍照。場景不變，保持現在的場景。可以適當改變人物的表情和肢體動作，是自然的狀態下拍出來的一張照片。用徠卡攝影，寫真紀實攝影
```
