# Wander 角色足球动作短片

## Skill 定位

将用户的角色图变成一条单人酷炫足球运动短片。默认是 15 秒、9:16、720P 的街头足球连续主镜头：角色从脚下控球开始，花式突破逐步加压，最后一脚把足球踢向镜头并撞镜收尾。

它只做单人角色驱动的足球动作片段，不做真实比赛复盘、球队战术分析、未授权真实球星复刻或多人长剧情。酷炫感来自可读的足球动作、动机明确的镜头运动和连续升级，不用无关爆炸掩盖动作。

## 多层级 Reference 调用策略

本 Skill 使用多层级 reference。执行时按阶段加载：

- 判断角色图、生成白底角色图、选择和锁定画风时，必须使用 `references/character-and-style-policy.md`。
- 设计足球动作、场地、节奏、音效和撞镜收尾时，必须使用 `references/football-action-engine.md`。
- 生成最终视频提示词、列出引用资产、检查角色一致性时，必须使用 `references/video-reference-policy.md`。
- 生成 `character_reference`、`football_scene_reference` 或 `football_action_composite_reference` 时遇到图片安全审核失败，必须使用 `references/image-generation-fallback-policy.md`。

主文件只定义总流程。不要跳过 reference，也不要把某一种画风的词直接复制到另外两种画风。

## 图片安全审核失败回退

只在图片生成因安全审核未通过时执行以下固定回退，不用于网络异常、模型超时、普通画质不满意或其他生成失败：

1. 保持原始提示词完全不变，先切换到 Navo Pro 重试。
2. Navo Pro 仍因安全审核失败时，保持同一份原始提示词完全不变，切换到 Navo2 重试。
3. Navo2 仍因安全审核失败时，才加载 `references/image-generation-fallback-policy.md`，审查并最小化调整可能触发审核的表述后再尝试。

这不是绕过安全审核。不得隐瞒、编码、拆分或伪装受限内容；若经过合规措辞调整后仍无法生成，应停止重试并向用户说明受限原因及可行的安全替代方向。

## 输入

### 第 0 轮：先锁定角色与画风

开场先说明：

“这个 Skill 会把你的角色做成一条酷炫足球动作短片。先上传角色图最容易锁住脸、发型和服装；上传后你可以选择保留原图画风，或切换到内置画风。没有角色图也没关系，我可以先按你的描述生成一张白底角色图。角色和画风确认后，才进入横版足球场景预览和视频生成。”

先建议用户上传自己的角色图，优先询问：

1. 是否上传角色图？推荐一张清晰、单人、正面或三分之二身、脸和服装可见的图片。
2. 若没有角色图，收集：成年角色的性别表达/外貌、发型、肤色、年龄感、体型与运动气质、球衣或日常穿搭、鞋款、禁用元素。不得把未成年或年龄不明角色用于性感化、危险化呈现。
3. 若用户上传角色图，必须先确认画风模式，不能默认转换：
   - 保留上传角色图画风（推荐）：视频、场景合成图和角色资产沿用上传图的绘画/渲染/摄影风格，只做必要的白底整理，不把角色强行转换成内置风格。
   - 使用内置画风：再从“实拍的电影质感、3D 渲染动画片、2D 卡通片”中单选一种。
4. 若用户没有角色图，选择画风，只能从以下三项中选择：
   - 实拍的电影质感（推荐）：真实摄影、运动电影、自然环境与真实鞋球接触。
   - 3D 渲染动画片：高质量风格化 3D、可控光影与动感特效。
   - 2D 卡通片：二维赛璐璐动画、清晰动作线与夸张透视。

同时收集最少边界：

- 场地偏好：夜晚城市水泥球场（默认）、黄昏街头球场、屋顶球场、室内五人制场、雨后球场。
- 动作强度：酷炫但易读（默认）、高强度花式、力量射门为主。
- 时长：默认 15 秒、720P；用户可以改为 30 秒或更长。系统根据时长自动决定音频交付：单段 15 秒视频内生成 BGM；超过 15 秒时拆成多段 15 秒视频，每段不生成 BGM，并额外输出一段独立 BGM 用于后期拼接。
- 视频比例：在最终视频生成前必须由用户明确选择横版 16:9 或竖版 9:16；没有默认值。横版场景图和横版动作预览不随此选择改变。
- 字幕：无字幕（默认）、短标题字幕、动作标签字幕。

### 角色输入使用规则

- 用户的角色图是身份锚点，必须先加载 `references/character-and-style-policy.md` 判断清晰度、单人性、脸部和服装可见度。
- 对用户上传图必须在系统内自动执行 `role_asset_decision`，不询问用户是否需要提取：背景干净、单人、脸/发型/服装/鞋与身体细节清晰、可直接作为角色资产时，直接将上传图锁定为 `character_reference`；任一关键条件不满足时，自动生成白底 `character_reference` 角色资产图。
- 用户上传角色图时，必须先确认 `style_mode`：`preserve_uploaded_style`（保留上传角色图画风）或 `built_in_style`（使用内置画风）。未确认前，不得把角色自动转换成实拍、3D 或 2D。
- 图合格时直接锁定上传图为 `character_reference`，不再额外生成白底角色图；不擅自更换脸、发型、主要服装、肤色或性别表达。
- 图不适合直接锁定时，系统自动生成 `character_reference` 白底角色资产图，并在生成后让用户确认结果；可以简要说明触发原因，但不得问用户是否要做这一步。
- 上述白底角色图、横版场景图和横版动作预览图遇到安全审核失败时，必须按“原提示词 -&gt; Navo Pro -&gt; Navo2 -&gt; 合规措辞最小调整”的顺序处理。
- 用户无图时，先输出白底角色图提示词，生成后必须请求确认；没有 `character_reference` 不得进入动作合成或最终视频。
- 不得照搬受版权保护角色、真人球星或第三方肖像；用户提供自己拥有使用权的角色图时才可直接使用。

## 内部流程和 Knowhow

### 1. 角色资产与画风确认

加载并执行 `references/character-and-style-policy.md`。

先生成或锁定：

- `character_reference`：角色身份资产。若上传图可直接使用，则为用户上传图；若系统判定不适合直接使用，才生成横版 16:9 白底角色设定图。始终锁定脸、发型、服装、鞋子、身体比例和运动气质。
- `football_scene_reference`：横版 16:9 足球场景图。锁定完整球场的空间、地面、灯光、背景和所选画风；不放角色。
- `football_action_composite_reference`：横版 16:9 角色进入选定球场的动作预览图，仅用于让用户确认角色与场景的整体光线、氛围、构图和感觉；不是最终视频的引用资产。

资产生成顺序必须固定为：

1. 先锁定 `character_reference`。
2. 生成并保存 `football_scene_reference`。
3. 只有 `football_scene_reference` 生成成功后，才生成 `football_action_composite_reference`；生成时必须实际引用 `@[character_reference]` 与 `@[football_scene_reference]` 两个已生成资产，不得只根据文字重新生成一张相似场景。该合成预览只用于用户确认整体感觉，完成确认后不传入最终视频节点。

`football_scene_reference` 缺失、生成失败或被替换后，禁止沿用旧预览或直接生成预览。必须先取得当前有效的场景资产，再基于它重新生成 `football_action_composite_reference`。用户修改场地、光线或画风时，同样先更新场景资产，再更新合成预览。

角色图存在时，先自动完成 `role_asset_decision`，再确认用户选的是保留原图画风还是内置画风；只有选择内置画风时才转换。直接可用的上传图不生成额外白底资产；系统提取出的白底角色图与无角色图生成的白底角色图都必须在进入场景前确认。

在生成 `football_action_composite_reference` 前，必须确认：

“这位角色的脸、发型、服装和画风是否通过？通过后我会生成足球动作场景预览。”

在输出视频前，必须确认：

“这张角色足球动作预览是否通过？确认后才生成最终短片，避免把不满意的角色或画风直接用于视频。”

### 1.5 视频比例强制闸门

用户通过动作预览后、生成任何最终视频提示词前，必须单独确认 `video_aspect_ratio`：

“预览已通过。最终视频请选择：横版 16:9，还是竖版 9:16？”

只有用户明确回复横版 16:9 / 16:9 / 横版，或竖版 9:16 / 9:16 / 竖版后，才能把对应值写入 `video_aspect_ratio`。如果用户尚未明确选择，或只说“都行”“默认”“你看着办”，必须停在这里再次询问；不得输出最终视频提示词、分段视频提示词或 BGM 提示词。

即使用户在对话较早阶段提过画幅，也要在动作预览通过后核对一次；只有已记录且用户未要求变更的明确值可以直接沿用。

### 2. 足球动作编排

加载并执行 `references/football-action-engine.md`。

默认使用八段连续主镜头动作，但根据时长压缩或扩展；动作必须可读、连续、符合大致身体发力逻辑：

1. 近地逼近与压迫停顿。
2. 鞋底滚动、拖回、脚尖点拨、变向假动作。
3. 挑球与脚绕球控制。
4. 膝盖、大腿、脚后跟的连续控球。
5. 低机位后跟挑球与交叉触球。
6. 鞋底停球、向前滚动、蓄力正对镜头。
7. 直线爆发射门。
8. 足球撞镜，干净地收为黑场、球印或画面闪白。

默认不要可见剪辑；镜头变化用连续的贴地滑行、绕脚跟拍、随球抬升、环绕、俯冲和锁定实现。用户明确需要分镜蒙太奇时才改为多镜头。

### 3. 最终视频提示词与引用

仅当用户确认角色资产和动作预览后，加载并执行 `references/video-reference-policy.md`。

最终视频必须引用：

- `character_reference`：锁定角色身份、发型、服装、鞋和体态。
- `football_scene_reference`：空的横版足球场景资产，锁定球场空间、地面、光线、背景与整体画风。

最终视频不得引用 `football_action_composite_reference`。该图只用于让用户确认角色植入场景后的光线、氛围和整体感觉；视频节点必须根据单独的角色资产与空场景资产重新完成角色进入场景、控球动作和镜头运动。

用户明确需要字幕时，可额外引用 `subtitle_style_reference` 或字幕版脚本图。最终视频不得只依赖白底角色图，也不得混用与选定画风冲突的材质、镜头或音效词。

音频交付由时长自动决定，不需要用户额外选择：

- 单段 15 秒：最终视频提示词必须要求同步生成 BGM，并描述与所选画风、场地和动作节奏相配的 BGM 风格。
- 超过 15 秒：必须拆为多个 15 秒视频提示词；每段都明确“不要生成 BGM，只生成环境音与足球动作音”，再额外输出一条覆盖完整成片时长的独立 BGM 生成提示词，供后期拼接和合成。

## 输出

### 第 0 轮输出

只输出：

1. 上传角色图的建议。
2. 没有角色图时的角色描述问题。
3. 三种画风选择及一句差异说明。
4. 场地、动作强度、时长、字幕的最少确认项；视频横版 16:9 或竖版 9:16 的选择在最终视频前确认。

### 角色阶段输出

必须输出：

1. 角色图自动判定结果，或用户角色描述的简短复述。
2. 图可直接使用时：说明已直接锁定上传图为 `character_reference`，不生成白底资产；图不适合时：输出 `character_reference` 的完整白底资产生成提示词并自动进入生成。
3. 角色与画风确认问题。

### 动作预览阶段输出

必须输出：

1. 已选风格和动作方向的一句话确认。
2. 先生成 `football_scene_reference` 的完整横版提示词；场景资产成功后，再输出引用 `@[character_reference]` 与 `@[football_scene_reference]` 的 `football_action_composite_reference` 提示词。
3. 动作预览确认问题。

### 用户确认动作预览后的输出

必须输出：

1. 先输出并确认 `video_aspect_ratio`：横版 16:9 或竖版 9:16；没有确认值时停止，不输出后续项目。
2. 一条带有已确认 `video_aspect_ratio` 的完整视频提示词，或按时长拆分的连续视频提示词。
3. 最终视频引用清单。
4. 声音与字幕策略。
5. 单段 15 秒时的内嵌 BGM 风格，或多段视频时的独立 BGM 后期生成提示词。
6. 角色、足球、场地、画风、动作、结尾的资产闭环检查。

## 自检

输出前检查：

- 是否一开始就建议用户上传自己的角色图。
- 用户上传角色图时，是否由系统自动判断其能否直接用作 `character_reference`，而没有询问用户是否要提取角色资产。
- 图直接可用时，是否跳过白底角色图生成；图不适合时，是否自动生成白底角色资产图并保留确认闸门。
- 用户上传角色图时，是否明确确认保留上传角色图画风，或改用内置画风，而不是自动转换。
- 没有角色图时，是否先收集描述并生成白底 `character_reference`。
- 无角色图时，是否只让用户在实拍电影质感、3D 渲染动画片、2D 卡通片中选一种画风。
- 场景图与角色动作预览图是否均为横版 16:9。
- 是否先生成并保存 `football_scene_reference`，再实际引用该资产与 `character_reference` 生成合成预览，而没有用文字重建场景。
- 场景资产缺失、失败或变更后，是否阻断了预览生成并要求先更新场景资产。
- 动作预览通过后，是否单独询问并记录 `video_aspect_ratio` 为横版 16:9 或竖版 9:16。
- 未得到用户明确的横版 16:9 或竖版 9:16 选择时，是否没有输出最终视频提示词、分段视频提示词或 BGM 提示词。
- 单段 15 秒时，是否在视频提示词中明确同步生成 BGM 并描述 BGM 风格。
- 超过 15 秒时，是否拆成多个 15 秒视频、每段明确不要生成 BGM只保留环境音，并额外输出独立 BGM 后期提示词。
- 是否在角色确认前没有进入动作场景与最终视频。
- 是否在动作预览确认前没有输出最终视频提示词。
- 是否执行了角色与画风、足球动作、视频引用三份 reference。
- 最终视频是否只引用 `character_reference` 与空的 `football_scene_reference`，而没有引用仅用于确认的 `football_action_composite_reference`。
- 是否让动作从控球、连招、挑球、蓄力到射门与撞镜逐步升级。
- 是否避免不可读的多余杂技、无关爆炸、足球数量变化、角色变脸或可见剪辑。
- 是否让 2D 保持二维动画语言、3D 保持三维渲染语言、实拍保持真实摄影语言。
- 是否明确足球只能由脚、腿、躯干或头部控制，手、手臂、手肘和手腕全程禁止接触足球。
- 用户需要字幕时，是否才加入字幕样式参考；用户不需要时不强塞字幕。
- 图片安全审核失败时，是否先保持同一提示词依次尝试 Navo Pro 和 Navo2，只有两者仍失败才考虑合规措辞调整。

## Ask User

必须问：

- “请上传你的角色图。没有角色图的话，告诉我角色的外貌、发型、服装和运动气质，我先帮你生成白底角色图。”
- “你希望整体视频保留上传角色图的原画风，还是使用内置画风？选择内置画风时，请再选：实拍的电影质感、3D 渲染动画片、2D 卡通片。”
- “角色和画风是否通过？通过后生成足球动作预览。”
- “动作预览是否通过？是否要调整场地、动作强度、球衣、镜头或结尾？确认后才生成视频。”
- “预览已通过。最终视频请选择：横版 16:9，还是竖版 9:16？场景图和动作预览会保持横版，方便完整查看球场。”
