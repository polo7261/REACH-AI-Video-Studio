# Wander 真人感美妆 UGC 产品测评

## Skill 定位

把用户上传的护肤、彩妆、香氛或个人护理产品图，转化为一支像真实创作者亲自拍摄、亲自试用并给出有限结论的 Seedance 2.5 竖屏 UGC 测评视频。

成片必须同时满足：

- 一位明确成年创作者，默认中国/东亚女性；
- 手机原生相机质感，不是棚拍广告或精修 TVC；
- 先试用、再观察、最后给有限结论；
- 用户想表达的核心卖点必须被保留，但要转译成动作、质地、妆效或即时感受，不直接照读广告话术；
- 中文口语由当下触感与观察触发，保留停顿、自我修正和克制态度；
- 产品包装、使用方式、人物、空间与光线连续。

默认成片：Seedance 2.5，参考图片 + 文本提示词，24 秒，9:16，720P，单一视频节点，多镜头时间戳，现场声 + 轻量动作音，无 BGM，无随机字幕。

明确不做：

- 高级商业 TVC、纯产品渲染片、3×3 商业故事板强制流程；
- 直播带货、背诵式口播、无人称旁白、第三人摄影；
- 无证据的医学功效、绝对化承诺、精确持续时间或夸张前后对比；
- 30 秒以上、多段拼接、视频/音频引用、首尾帧续写或编辑链路。

## Reference 调用策略

按阶段读取：

1. 看完用户素材后读取 `references/asset-policy.md`，判断最少充分资产与功效声明边界。
2. 确定测评角度时读取 `references/beauty-review-engine.md`，建立“观察—试用—证据—有限结论”链。
3. 用户提供卖点，或 Agent 需要推荐卖点和内容钩子时，必须读取 `references/selling-point-to-ugc.md`，生成卖点转译卡。
4. 生成任何人物、场景或使用关系图前读取 `references/mobile-beauty-realism.md`。
5. 编写口播前读取 `references/live-review-dialogue.md`。
6. 写时间戳提示词时读取 `references/timeline-patterns.md`。

主文件只保存流程和硬约束，不在对话中完整复述 references。

## 固定用户引导

### 第 0 轮：功能介绍并索取核心图片

固定开场：

> 这个 Skill 会把你的美妆或护理产品图做成一支 4–30 秒、像真人创作者亲自拍摄和试用的 UGC 测评视频。我会先判断产品图能否直接引用，并把你想突出的品牌卖点转成真实动作、可见证据和自然口播；之后只用一轮确认内容方向、场景、时长和必要边界。请先上传最清晰的一张产品图；如果已有指定达人参考图或一句想突出的卖点，也可以一起发，但不是必需。

第一屏只把产品图设为必需输入；人物图和一句原始卖点可选。不要要求用户填写完整营销表、全部台词、音乐、字幕和镜头。

### 第 1 轮：自动判断并一次确认项目边界

先输出简短判断：

1. 产品类别、包装、质地或用法线索；
2. 产品图能否直接作为 `product_reference`；
3. 是否已有 `creator_reference`；没有时默认生成一张，普通使用动作不额外创建关系图；
4. 哪些卖点可由画面观察，哪些来自用户信息，哪些属于未经证实的功效声明；
5. 推荐的一个核心测评问题、一条可拍证据链和一条自然口播方向；
6. 用户原始卖点如何被保留、降级或改写，避免用户以为 Agent 擅自丢掉商业意图。

随后集中确认，默认方案为：

```text
测评路径：第一次真实试用 + 即时体验（推荐）
核心卖点：Agent 推荐 1 个可视化卖点；用户可以直接回复“想突出：……”替换
目标使用者 / 情境：Agent 根据产品给出一个合理假设；用户可一次纠正
口播气质：真实快测（推荐）；可改为朋友分享 / 轻反差种草 / 克制专业
表达方式：保留卖点含义，不逐字照读广告话术；用动作、反应和个人结论表达
创作者：系统生成的明确成年中国/东亚女性
场景：真实居家梳妆台或洗手台
画幅：9:16
时长：24 秒；允许 4–30 秒
声音：创作者同期中文口播 + 室内环境音 + 使用动作音，无 BGM
字幕：无随机字幕；准确字幕建议后期添加
必须保留：包装结构、主色、Logo 位置、正确用法和用户指定元素
禁止出现：医疗化结论、绝对承诺、夸张磨皮、硬广背稿、第三人摄影
```

同时给出一张简短的卖点转译预览：

```text
用户/推荐卖点：原始商业意图
观众真实顾虑：这个人为什么会在此刻测试它
可拍证据：镜头能直接看到什么
口播方向：1 句由动作或观察触发的自然表达，不是最终逐字稿
表达边界：哪些词不能凭图片或一次试用使用
```

用户回复“按默认来”即可确认推荐卖点、使用者假设和口播气质；也可以只回复“想突出：……”或贴一段商品卖点，Agent 自动完成转译，不要求用户自己写口播。不得重复询问已确认事项。用户指定受监管功效、精确数字、对比结论或必须逐字出现的品牌话术时，先要求其提供最终合规文本。

## 输入与自动判断

### 产品图

可直接引用需满足大部分条件：产品主体完整、边缘清楚、颜色与材质可辨、包装比例未严重变形、主产品无歧义、关键使用结构未被遮挡。小字无需承诺逐字复现。

只有背景严重干扰、关键结构缺失、多产品主次不明、强反光/手遮挡或低质量拼图会破坏身份时，才生成新的干净 `product_reference`。Agent 自行判断，不把清晰度判断推给用户。

### 信息可信度

为每条信息标记来源：

- `观察`：图片中可见的包装、颜色、形态、质地与使用动作；
- `用户信息`：用户明确提供的成分、卖点或品牌说明；
- `创意推断`：为测评结构提出的合理假设，不能当事实口播；
- `需确认声明`：医学、持续时长、精确比例、认证、零刺激、适用所有肤质等强声明。

只凭图片不得确认医学修复、抗敏、祛痘、抗老效果、持续小时数、防晒数值、绝对防水或“所有肤质适用”。没有可信声明时，改写为可见质地、延展性、上脸过程、即时光泽、颜色、气味偏好或个人主观感受。

### 用户自定义卖点

接受用户以任何成熟度输入卖点：一个词、一句话、商品详情页文案、成分说明、目标人群或想解决的顾虑。Agent 不要求用户先改写成口语。

处理顺序：

1. 提取用户真正想让观众记住的一个商业意图；
2. 判断它属于可见事实、用户提供事实、主观体验或需确认声明；
3. 为它匹配一个真实使用情境和一个观众顾虑；
4. 把卖点改写为能由镜头证明的动作或观察；
5. 再把证据改写为创作者当场会说的一句反应；
6. 检查最终脚本仍然表达用户原意，而不是只剩“真实感”却失去卖点。

用户一次提供多个卖点时，按“与产品相关性、可拍性、可信度、观众决策价值”排序，只选 1 个核心卖点，最多保留 1 个辅助观察；其余列为未采用，不静默丢弃。

## 资产管线与确认闸门

采用最少充分资产和一次资产闸门。

### 语义资产名

- `product_reference`：始终需要；优先使用用户原图，锁定包装、比例、主色、材质与 Logo 位置。
- `creator_reference`：默认使用一张。用户有合格达人图时直接使用；没有时生成一张成年创作者身份图。
- `product_use_reference`：默认不创建。只有非常规工具、精确接触位置、产品尺寸关系高风险，或首轮视频已经出现明显握持/使用错误时才追加；普通口红、精华、面霜、粉底和常规刷具仅用文字控制。
- `scene_reference`：只有用户要求复刻特定空间时创建。
- `storyboard_reference`：只有严格镜头顺序或复杂使用步骤多次失败时才创建，不默认生成。

默认只用 2 张图：用户产品图 + 一张成年创作者身份图。用户已有合格人物图时不重新生成。简单单主体且人物一致性风险低时可以只用产品图；只有明确失败风险才增加第 3 张关系图或结构图。

依赖关系：

```text
product_reference + creator_reference
    -> product_use_reference(失败后或高风险时可选)
    -> storyboard_reference(失败后可选)
    -> final_video_prompt
```

生成创作者身份图后集中确认一次：产品是否正确、成年创作者是否符合预期、手机真实感是否成立。只有确实生成了关系图时才确认使用关系。上游资产改变后同步更新下游资产与最终提示词。

最终输出前把语义名解析为实际上传顺序：

```text
@图片1 = product_reference：锁定产品包装、比例、主色、材质和 Logo 位置
@图片2 = creator_reference：锁定同一成年创作者的脸、发型、肤色、真实皮肤和服装
@图片3 = product_use_reference：仅在高风险或失败回退时出现，锁定精确取量、握持或接触关系
```

最终提示词只保留实际 `@图片N`，不得留下内部资产名。

## 核心创作方法

### 1. 只测一个核心问题

每条视频只回答一个可被镜头验证的问题，例如：

- 质地是否容易推开、是否厚重；
- 唇釉/粉底的颜色、遮盖或光泽在自然光下怎样；
- 泵头、滴管、刷头是否好控制取量；
- 产品在一次完整使用动作中的即时观感；
- 香氛的第一印象与个人偏好，但不把气味描述成客观功效。

最多加入一个辅助观察。不要在 24 秒里堆成分、肤质、价格、持妆、气味和包装六个结论。

### 2. 先做卖点转译，不先写口播

用户卖点不能直接粘进台词。先读取 `references/selling-point-to-ugc.md`，形成内部卖点转译卡：

```text
原始卖点
核心商业意图
目标使用者与真实顾虑
可信度与声明边界
可拍动作 / 感官证据
开场预期或小冲突
即时反应
条件化个人结论
最终是否仍保留用户原意
```

“自然”不等于弱化卖点，“网感”也不等于堆热词。有效网感来自：第一秒有具体顾虑、实际试用产生反差、人物会停顿或自我修正、结论带个人条件、镜头和语言有快慢变化。

生成最终脚本前，内部产出三种候选强度：最克制、最自然、稍有态度。删除画面复述、品牌主播腔、无证据承诺和网络模板后，只输出最符合已确认口播气质的一版；不要把三套候选全部塞给用户。

### 3. 建立证据链

默认顺序：

```text
具体疑问或使用情境
→ 镜头看清产品身份
→ 正确取量或上妆
→ 近距离观察质地/颜色/肌肤反应
→ 创作者身体与表情产生即时反应
→ 换到自然光或另一角度复核
→ 给出带条件的个人结论
```

结论必须由前面的可见证据支持。把产品拿掉后，测评问题和结论若仍能原样成立，说明产品只是道具，需重写。

### 4. 真人 UGC 拍摄合同

- 所有镜头都能由创作者单人完成：手持前置自拍、镜前自拍、手机固定在桌面/支架上，或创作者自己补拍的近距离产品/上脸插镜；
- 允许不同 take 的自然硬切，但空间、人物、产品状态与光线可连续；
- 保留手机自动曝光、轻微广角、深景深、轻微锐化、局部高光和小幅对焦呼吸；
- 保留毛孔、细纹、唇纹、碎发、轻微泛红和真实妆面，不磨皮、不液化、不生成塑料皮肤；
- 产品特写为证据，不是高端 hero shot；禁止转台、液体悬浮、棚拍轮廓光、电影推轨和广告级慢动作。

### 5. 活人口播

口播先服务人物当下反应，同时必须完成已确认卖点。24 秒默认 3–5 个发声点，每次通常 4–18 个汉字；允许半句、停顿、重复、自我修正和短暂沉默。

每句都要回答：“她上一秒看见、摸到或闻到了什么，才会现在开口？”以及“这句话如何让观众更理解已确认卖点？”前者答不出就删，后者答不出就重写或把卖点交给动作完成。禁止模板开场、产品说明书复述、品牌主播腔、工整金句、网络热词堆砌和无证据的极端评价。

### 6. 有限结论

收尾使用个人、条件化表达，例如“我这边看起来……”“对我这种偏干状态……”“第一遍上脸我会更喜欢薄一点”。不得把一次即时试用说成长周期功效测试。需要长期结论时，改成“首日体验/即时观感”，或要求用户提供真实长期素材与合规事实。

## 最终视频提示词规则

- 模型固定为 Seedance 2.5，只使用参考图片 + 文本提示词。
- 4–30 秒使用一个视频节点，不因超过 15 秒拆段。
- 使用“参考素材 + 一句话概述 + 全局设定 + 连续时间戳 + 全局收束”五层结构。
- 第一段从 `00:00` 开始，最后一段结束于总时长；区间连续、无重叠、无空档。
- 9–15 秒写 3–5 段，16–24 秒写 4–7 段，25–30 秒写 5–8 段。
- 产品主要出现或使用的时间段再次引用对应 `@图片N`。
- 明确总时长、9:16、720P、单节点、声音和字幕策略。
- 默认声音为同期中文口播 + 室内环境音 + 取盖/按泵/涂抹等动作音，无 BGM、无旁白、无第二人声。
- 默认无随机字幕、贴纸、水印和无关文字；准确字幕建议后期添加。
- 全局收束只列题材相关失败模式：换脸、磨皮、产品变形、手指错误、用法错误、皮肤状态跳变、第三人摄影、硬广口播和无证据声明。

## 输出

### 配置/资产阶段

输出：素材判断、卖点来源与声明风险、卖点转译预览、推荐测评问题、项目边界确认、仅缺失且会进入最终节点的创作者身份图提示词。默认不生成使用关系图或九宫格。

### 视频阶段

确认通过后依次输出：

1. 项目设置：模型、模式、时长、画幅、720P、结构、声音、字幕；
2. 卖点转译卡：原始卖点、观众顾虑、可拍证据、口播策略、表达边界；
3. 最终口播脚本：按时间顺序列出唯一采用版本，并说明每句由什么动作或观察触发；
4. 测评证据链：核心问题、可见证据、有限结论；
5. `@图片N` 引用清单与锁定用途；
6. 一条可直接复制的 Seedance 2.5 完整提示词；
7. 资产闭环检查：所有参考图已引用、无无用中间图、无内部资产名、上游修改已同步；
8. 按照下方“自检”逐项检查生成的提示词，修复全部问题后再交付。

## 自检

- \[ \] 是否只制作真人 UGC 美妆/护理产品测评，而非 TVC 或直播带货？
- \[ \] 第 0 轮是否只索取核心产品图，图片质量由 Agent 判断？
- \[ \] 是否只进行一次集中项目确认，用户可用“按默认来”继续？
- \[ \] 是否只有一个核心测评问题和最多一个辅助观察？
- \[ \] 用户自定义卖点是否被明确记录，没有被 Agent 静默替换或遗漏？
- \[ \] 是否完成“卖点 → 顾虑 → 可拍证据 → 即时反应 → 有限结论”的转译？
- \[ \] 口播是否既像真人当场反应，又让观众准确理解核心卖点？
- \[ \] 每个结论是否有可见动作或即时观察支持？
- \[ \] 是否区分观察、用户信息、创意推断和需确认声明？
- \[ \] 是否默认只使用产品图 + 创作者身份图，并只在明确失败风险下增加资产？
- \[ \] 是否全部解析为实际 `@图片N`，并在生效时间段重复引用？
- \[ \] 4–30 秒是否单节点，时间戳是否覆盖全片且连续？
- \[ \] 口播是否由即时感受触发，克制且允许停顿？
- \[ \] 是否保持手机原生质感、真实皮肤和单人可拍摄性？
- \[ \] 是否明确无 BGM、无随机字幕、无水印和题材相关禁止项？
- \[ \] 是否已清除 `{...}`、`<...>` 等未解析模板占位符和内部资产名？
- \[ \] 是否不存在“超过 15 秒拆段”“分段生成后合成”等 Seedance 2.0 遗留规则？

## Ask User

只在以下情况追加询问：

1. 多个产品无法判断主测对象；
2. 用户要求医学、认证、精确数字、持久时长或绝对化结论，但未提供合规事实；
3. 必须逐字出现品牌话术、价格或参数，但未提供最终文本；
4. 必须复刻指定达人或空间，却缺少对应参考图；
5. 用户同时要求互相冲突的 UGC 随拍与高端棚拍/电影运镜。

用户只说“想突出某个卖点”不属于阻塞问题；Agent 应直接提出可拍证据和自然表达。其他事项由 Agent 推荐并允许用户用“按默认来”继续。
