## A Single Wes Anderson Base + One Optional Dominant-Color Line (Distilled in Stage 1, Unified Across the Whole Film)

Wes Anderson has only **one rendering base** (symmetry, flatness, frontal flat lighting, 35mm texture, live-action photorealism), locked down by the scene seed to guarantee consistency across the whole film. The palette **has no fixed preset** (the style is already baked into the seed); instead, **one line on the dominant color tendency is distilled from the script's mood** and appended to the MJ prompt; if the user doesn't specify, the seed's native palette has the final say.

- **Base clause (for MJ scene images)**: `symmetrical storybook-style cinematic frame, perfectly centered dead-center one-point perspective composition, stage blocking flattened like a theater set, photorealistic live-action photography, meticulous art-directed set design, soft even frontal flat lighting, restrained finely-tuned pastel palette, delicate 35mm film texture, precise and orderly`
- **Front-loaded style sentence (placed as the first sentence of the Seedance prompt)**: `Symmetrical storybook-style cinematic frame, perfectly centered dead-center one-point perspective composition, flattened stage blocking, photorealistic live-action photography, soft even frontal flat lighting, finely-tuned pastel palette, delicate 35mm film texture, precise and orderly camera movement.`

**Optional one-line dominant color tendency (distilled from the script's mood; appended after the base clause; not mandatory)**:

- Warm candy comedy: `warm-leaning palette — blush pink, cream, butter yellow, with a touch of true red`
- Cool-toned melancholy: `cool-leaning palette — teal, faded navy, powder blue, paired with cream white`
- Autumn earth tones: `autumn-leaning palette — mustard yellow, ochre, warm brown, forest green`
- Vintage fade: `vintage-faded palette — dusty rose, olive, tan, dark gold`
- Or write another line to fit the script — at most one slightly brighter accent color, with everything else pressed into a harmonious palette.

## Fixed Seed & Image-Generation Specs (Quick Reference)

- **Pick-one-of-four position labeling (MJ image generation only)**: for any **set of 4 scene images generated by MJ (2×2 grid)**, the agent's options must **state which position 1/2/3/4 corresponds to** — **1 (top-left), 2 (top-right), 3 (bottom-left), 4 (bottom-right)**, e.g., `1 (top-left)`, `2 (top-right)`, `3 (bottom-left)`, `4 (bottom-right)`, so the user can accurately point to one. **Character costume images generated by Lib Image do not follow the 2×2 grid and are not position-labeled.**

- **Scene/lighting images = Midjourney V8.1**, fixed seed `--sref 4926062650 --profile rhc51rh`, **wide shot with no people, zero text, symmetrical, photorealistic live-action** (characters are composited into the frame later in Seedance).\
  Suffix: `… --sref 4926062650 --profile rhc51rh --ar <4:3|16:9|1:1|9:16> --v 8.1 --no people, text, words, letters, numbers, subtitle bars, signage text, logo, watermark, extraneous patterns, cartoon, illustration, miniature model, asymmetry`

- **Characters + costume three-view sheets = Lib Image** (mandatory, replacing MJ for character generation): **all characters are generated together in one pass** — one **16:9 landscape composition** per character (containing **4 sets of front-facing full-body costume options**); once every character is generated, do a single pick-one-of-four/confirmation for each; after confirmation, **take each character's selected costume image as the image input (editing/image-to-image), use it directly as the front view of the three-view sheet, and only generate the side/back views to complete it**; all characters' white-background front / side / back three-view sheets are generated together, **photoreal human model**; **only the three full-body views — front, side, back — no headshots/head close-ups**; **never regenerate the three views from a rewritten text description** — face and costume details (hairstyle & hair color, style & cut, collar & cuffs, buttons & pockets, prints & patterns, fabric, shoes & socks, accessories, every color) are copied item by item from the selected image; only the viewpoint changes.

  - **With original face material** → the three-view sheet uses a **white circular sticker covering the face**, and adds **small Chinese text in the bottom-right corner of the image: 「人脸单独提供 · 此图仅用于服装造型参考」** (identity is locked in Seedance by the original face); **without an original face** → keep the face of the selected costume image (the face is the identity, not covered).
  - Key instruction (an editing instruction using the selected costume image as image input, not a from-scratch description): `Use the selected costume image as the image input; keep the exact same person and costume; reuse it as-is, unchanged, as the front view, and generate only the side-view and back-view full-body shots of the same model; the entire sheet contains only the three full-body views — front, side, back — with no headshots/head close-ups/face close-ups of any kind; every detail matches the reference image 1:1 — same face, hairstyle and hair color, garment tailoring and silhouette, collar/cuffs/hem, buttons/zippers/pockets, prints and patterns, fabric texture, shoes, socks, every accessory, every color; do not repaint the face; do not redesign, add, or remove any costume detail; pure white seamless background, soft even studio lighting, photorealistic (only when an original face exists: cover the face with a white circular sticker and add small Chinese text in the bottom-right corner of the frame: 「人脸单独提供 · 此图仅用于服装造型参考」)`
  - For multiple characters, generate one by one and maintain a **cast sheet** (name/role/costume). Note: Lib Image has no `--sref`; consistency relies on a detailed character card + reference images + "keeping the same model across views".

- **Video = Seedance 2.0**, inputs = scene image + the relevant characters' white-background three-view sheets (locks costume/body shape) + **face reference** (with an original face → the original face image/video; without → the selected costume image); multi-character shots feed multiple character references.

## Workflow (Pause for Confirmation at Each Stage)

### Stage 0 · Three Pre-Shoot Questions (Asked in Separate Turns, One at a Time; Ask the Next Only After the Current One Is Answered)

1. **Script / text** (primary driver):

   - **With a script / text** → proceed directly to Stage 1 and parse it into storyboard shots and characters.
   - **No script** → first ask the user: "Can you express an idea/concept in **one sentence**?" Once you have that sentence, **draft a short screenplay from it** (with characters, scenes, key narrative beats, a few lines of dialogue and narration, sized for a 15–30s short film), hand it to the user for confirmation/revision → after confirmation, proceed to Stage 1 parsing.
   - If the user can't even give one sentence, talk it through with them to land on a sketch concept, then draft as above.

   > Pause for confirmation after drafting the script, then continue.

2. **Characters + costumes**: ① Any face/character references (image or &lt;15s video)? ② Any costume direction or costume reference images? Route into one of the three Cases below.

3. **Spoken language**: characters/narration default to **the script's own language**; note it down if something else is specified.

**Three Cases (in every Case, first "understand the costume direction + expand it into a complete written spec drawing on Wes Anderson costume language", then generate — without discarding the image in favor of a text-only copy; afterwards, uniformly: Lib Image generates front-facing full-body costume options → confirmation → Lib Image generates the white-background three-view sheet)**:

- **Case 1 — costume reference image available**: the costume image serves as an Image Reference + the expanded written spec; Lib Image generates the costume options/three-view sheet; if there is no face reference, the three-view sheet keeps the face (face = identity).
- **Case 2 — face available, no costume image**: the face image serves as an Image Reference + the expanded written spec; Lib Image generates the costume options/three-view sheet; **the original face image is carried into Seedance to lock the face; the three-view sheet covers the face with a white circular sticker + small Chinese text in the bottom-right corner: 「人脸单独提供 · 此图仅用于服装造型参考」**.
- **Case 3 — neither available**: follow up by asking **sex (male/female) + ethnicity (Asian/Western/other)**, expand the written spec, and Lib Image generates the costume options/three-view sheet directly; **the face of the selected costume image is the identity (the three-view sheet keeps the face) and serves as the Seedance face reference**.
**Wes Anderson costume language (align when writing up the spec)**: `Wes Anderson costume language — retro mid-century/vintage tailored, well-fitting clothing, uniform-feel matching sets, characterful accessories (berets, knee-high socks, letter monograms, tailored jackets, round-frame glasses), period-accurate props, precisely symmetrical styling, colors unified within the film-wide palette`; the emotion tier does not alter the styling baseline, only fine-tunes the color scheme per the script.

### Stage 1 · Script Analysis + Final_Video_Spec

**Script Analysis (narrative backbone, must be output, requires confirmation)**:

- Narrative structure: whether it is chaptered / whether there is a **narrator** / narrative beats (take 1–2 beats for 15s, 2–3 beats for 30s).
- **Character list**: list all characters who appear + each one's identity/relationships.
- **Scene list**: the space of each scene.
- **Dialogue line by line**: mark the speaker and the original text (in the script's language). **Judge whether the dialogue is too long/cumbersome** — if the uploaded script's lines are verbose, **distill and condense them into short, punchy lines that fit 15/30s** (keep the dramatic core and character relationships, cut the excess); condensing changes must be explained to and confirmed by the user.
- **Emotional tone**: the emotional arc of each scene/each character (used for performance assignment in Stage 4).
- **One-line dominant color tendency**: distilled from the tone (see above).

**Final_Video_Spec (user decides)**: **aspect ratio** (default **4:3 Academy**, open to 16:9 / 1:1 / 9:16) / **quality** (480p · 720p · 1080p) / **duration** (**15 or 30s**, choose one). Duration determines segment count: 15→1 segment, 30→2 segments; each segment = one 15s clip.

> Pause for confirmation (script analysis results + spec).

### Stage 2 · Character Design (Lib Image)

**Generate all characters in one batch** (do not finish one character, confirm, then move to the next): for each character write a character card, then Lib Image **generates all characters' look images together** (one 16:9 landscape composition per character, containing 4 front-facing full-body looks) → **pause once, letting the user pick one of four for each character** → **pause for confirmation (all characters together)** → use each character's selected look image as image input (edit/img2img): the selected front image directly serves as the three-view's front, only the side/back are generated to supplement; **output all characters' white-background three-view images together** (real human models, **containing only the three full-body views front/side/back, no headshots or head close-ups**; with an original face → a white circular sticker covers the face + small Chinese text in the lower-right corner 「人脸单独提供 · 此图仅用于服装造型参考」 ("Face provided separately · This image is for costume-styling reference only"); without an original face → keep the face); **face and costume details strictly follow the selected image, never redraw the front face or redesign the clothes**; after the images come out, **check face and costume details item by item** (hairstyle, style and cut, collar and cuffs, buttons and pockets, prints, fabric, shoes and socks, accessories, colors); if any item is off, re-generate that character's side/back using the selected image as input; if it keeps drifting, for that character assemble the three views directly from "selected front image + the two side/back images" → **pause once more for confirmation (all characters' three-views together)**. Maintain the cast sheet. For costume changes, additionally produce "Look 1/Look 2".

### Stage 3 · MJ Scene Tone Images (V8.1, seed `--sref 4926062650 --profile rhc51rh`)

Per the scene list, **generate all scenes together** (do not finish one scene, confirm, then move to the next): for each scene generate 1 set of 4 symmetrical panoramic empty-scene images (space type + symmetrical layout + key objects + dead-center one-point-perspective composition), **panoramic, no people, zero text, live-action photorealistic**, appended with the base-quality sub-clause + the one-line dominant color + the scene seed tail string (see the quick reference).\
**All scene images generated in one batch → one single pause, letting the user pick one of four for each scene (options must be labeled** `1(top-left)/2(top-right)/3(bottom-left)/4(bottom-right)` **by position) → proceed to Stage 4 only after collecting all scenes' selections**; **it is strictly forbidden to enter Stage 4 without the four-choose-one**.

> 🛑 Mandatory gate: after all scene images are generated, stop in one go and wait for the user's four-choose-one per scene; do not enter the next stage before all scenes' selections are collected.

### Stage 4 · Storyboard Script (must be output before video generation, requires confirmation) — the centerpiece

**Output segment by segment, shot by shot, in tables**; one table per segment, one row per shot, columns as follows:

Shot # Frame (character blocking + performance + scene + symmetrical composition) Dialogue/Narration (mark speaker · script language) Delivery tone Seconds Camera movement & on-screen framing Transition Continuity key points Shot 1………\~Xs Locked-off/lateral track/whip pan/hard push-in/overhead flat-lay/freeze-frame slow walk Hard cut/whip pan/match cut Positioning·axis·props·palette·beat

Field notes:

- **Delivery tone** is assigned per the script's emotions; do not default to deadpan.
- **Seconds**: the shots sum to 15s; per segment, **see the table below for the number of shots per 15s**; mark the whip-pan/hard-cut positions and the landing points of freeze-frame slow walks; transitions are basically never dissolves.
- **Continuity key points** fill in: character identity–costume–handheld prop / screen direction–180° axis–characters' L-R positions–set geography / same scene seed–dominant color–lighting direction–time of day / current beat–emotional continuation / (for 30s) action handoff from seg1's tail frame→seg2's head frame.

> Pause for confirmation (look images + three-view images + scene images + storyboard script tables).

### Stage 4b · 30s Tail-Frame Continuation (key mechanism for generating clip by clip)

After clip 1 is generated → use ffmpeg to extract the **tail frame** → **analyze the tail frame** (character blocking/expression/lighting/shot size/ongoing action) → generate clip 2 according to the seam mode declared in the storyboard:

- **(A) Continuous action**: the tail frame serves as Seedance's **starting frame**; clip 2 continues the action, seamless.
- **(B) Clean hard cut to a new camera setup**: the tail frame serves only as a continuity reference (characters/costume/palette/lighting); clip 2 is an all-new symmetrical setup; joined at assembly with a hard cut/whip pan/match cut.

> Place the big symmetrical hard cuts at the seam between the two clips wherever possible (highly divergent symmetrical hard cuts inside a single 15s clip are rather difficult for the model).

### Stage 5 · Seedance Video (one 15s clip per segment, generated one at a time)

Prompt structure (in order):

1. **Prepended style sentence** (unified across the whole film, see above).
2. **Character assembly**: white-background three-view locks the look/physique + face reference locks identity (original face → original face image/video; Case 3 → the selected look image); for multiple characters, feed multiple references. State explicitly: "each character's face comes from their face reference, their look from their three-view; place them into the scene image, keeping their real likeness".
3. **Storyboard**: `Shot 1 … cut to/whip pan to Shot 2 …`; one continuous 15s with the shot count up to standard; **transitions are mainly hard cuts/whip pans/match cuts, basically no dissolves**. Each shot = shot size (symmetrical camera position) + movement + performance (**assigned per the script's emotion**).
4. **Spoken layer**: line-by-line dialogue (mark the speaker, **lip sync**, **dialogue text in the script's language, Chinese or English**) + narration VO + delivery tone. Example (instruction in Chinese, dialogue filled with the script's original text): `The character opens their mouth and speaks the line with precise lip sync, narration in voice-over; line content: 「<original script line>」`.
5. **Movement**: `precise, meticulous camera work — locked symmetrical freeze-frames, smooth lateral dolly-track moves, whip-pan transitions, hard push-in/pull-out zooms, overhead flat-lay inserts, occasional freeze-frame slow walks`; a single continuous take only as needed.
6. **Audio + text rules**: dialogue/narration generated with the video, **music/SFX not generated (laid in at assembly)**: `dialogue and narration are spoken aloud within the video, no background music, no sound effects (added in post)`; **the number of people on screen strictly equals the number of script characters (red line: 5)**; negative prompt `subtitles, subtitle bars, extra people, background extras, crowds, additional people, on-screen text, sign text, logo, watermark, superfluous patterns, cartoon, illustration, miniature models, asymmetry, extra fingers, deformed hands`.
**Performance endowment (per script, deadpan not enforced)**: ≥1 expression + 1 action per shot; emotional intensity follows the scene (giddy/anxious/tender/dejected/restrained all fine), just wrapped in Wes Anderson's tidy shell (symmetry, steady blocking).\
**Universal anti-stiffness (added to every shot)**: `subtle breathing for a natural rise and fall of the chest, slight head movements, natural blinking, expression slowly shifting with the shot's emotion, relaxed natural posture, lively natural movements with ease-in and ease-out`.

> Generate one at a time, confirming each one.

### Stage 5 (Implementation Notes) · Narration Fallback

Narration is generated with the video by default (VO layer); if the model's support for "VO narration without matching mouth movement" is unstable, **fall back to assembled VO** (TTS/recording overlay); all other rules unchanged.

### Stage 6 · Assembly

1. **Joining**: the two 15s segments are joined via **hard cut / whip pan / match cut** (Wes Anderson doesn't dissolve); the generated clips already contain dialogue/narration.
2. **Sound bed**: uniformly **lay BGM / SFX** (the generated clips have no BGM/SFX to begin with).
3. **Add subtitles (**`add_subtitle`**)**: add subtitles for **character dialogue** — ask the user **Chinese / English / bilingual / none**, then per the choice build the dialogue's original text/translation into a subtitle track overlaid on the picture (not burned into generated frames, kept as an editable overlay layer); dialogue copy is taken from the dialogue recorded in Stage 1/4 (whether narration gets subtitles is up to the user). Subtitles are **added only at this step** and must never appear during SD2 video generation (see Red Line 3).
4. **Overlays**: logo / title / credits PNGs may be overlaid (never burned into generated frames).
5. Guide the export.

### Notes

- Don't write real directors' specific work titles / real actors' names into prompts; **reproduce the aesthetic, not a specific work or person** — the Wes Anderson feel is carried by descriptive words (symmetry, one-point perspective, flattened space, pastels, storybook, locked-off walking), while a director's name serves only as a lightweight MJ style cue.
- Wherever MJ is used, uniformly **V8.1**; scene images use the fixed seed `--sref 4926062650 --profile rhc51rh`; characters / styling uniformly go through **Lib Image**.
- Zero text in generated frames; all text (subtitles/titles/chapter cards/credits/logo) is overlaid only in assembly, never burned into generated frames.
- If the user only wants clips / a single shot, or has already specified scenes and styling, deliver as needed without breaking the rules on 15s / duration tiers / shot-count floors / symmetrical realism / dialogue & narration generated with the video / BGM & SFX laid down in assembly.
